## 用户决策与新增约束

- 档位:**结构重构 + SSE 实时化 + 提示词管线整合**,并**加强抗多模式提示词相互混淆设计**。
- 用户提醒:任务模式与角色扮演模式的「Agent 系统提示词」在设置面板**共用一个输入框**(`AgentSettingsSection.vue` 单字段 `v-model="agentSystemPrompt"`,load/save 按 `appMode` 带 `?mode=` 分流;后端 task 覆盖层为 `None` 时回退内置任务默认词 `default_task_agent_prompt()`,而非 roleplay 人设词)。重构必须:

## 背景与现状(已探明)

「任务模式」是与角色扮演平级的顶层模式(`appMode: 'roleplay' | 'task'`),一套独立于聊天引擎的 plan(LLM 拆解 2~5 步)→ execute(逐步派子任务)→ summarize(LLM 汇总)引擎,状态落 SQLite 三表(tasks/task_subtasks/task_usage),前端靠 1 秒 REST 轮询刷新,不走 SSE。核心代码:`server-rs/src/services/task_service.rs`(1270 行单文件)、`api/tasks.rs`、`web/src/stores/task.ts`(210 行轮询)、`TaskBoard.vue`/`Sidebar.vue`/`AgentPanel.vue`。

已确认痛点:

1. `task_service.rs` 单文件职责过载(CRUD+SQL+执行引擎+提示词渲染+JSON 打捞+usage+取消令牌);
2. `generate_step_retry`/`summarize_task_retry`/`plan_task_retry` 三份逐行同构的重试逻辑;
3. `list_subtasks()` 等 DB 读取路径 `unwrap`/`expect` 会 panic;
4. 任务状态在 DB/Rust/TS 三处裸 String 靠注释对齐(`types.rs:490` 注释已过期,漏 `planning`/`partial`);
5. 进度事件伪装成 SSE 事件实为前端合成,reducer 空操作;
6. 1s 轮询开销;
7. 任务侧与引擎侧各自重复实现世界书匹配/提示词注入/宏渲染;
8. 任务侧无引擎同款 `<UNTRUSTED_PROMPT_SOURCE>` 边界包裹,外部文本裸拼进 system;
9. 模式隔离仅靠 `for_mode()` 里 `agent_system_prompt` 一个 if 分支,属约定而非法式;
10. 测试缺口(stop 运行中任务、汇总空输出重试、`api/tasks.ts`、组件层)。

## 范围

**做**:后端 task_service 拆分与加固、状态枚举化、任务事件 SSE 实时化、前端订阅改造、提示词管线整合、抗混淆设计(类型级隔离 + untrusted 边界 + UI 标注 + 测试矩阵)、补测试、文档同步。

**不做**(明确范围外):聊天引擎内部重构(fast/deep/agent/custom 枚举化、`engine/mod.rs` 拆分、EJS/触发式世界书/状态块/MacroCtx 语义)不动;DB schema 不变(status 仍是 TEXT 不加 CHECK,避免迁移风险);UI 布局与样式体系不改(仅加模式徽标与一行说明);`agent_subtasks` 与 `task_subtasks` 两套体系不合并(有外键约束原因);端口 3001 契约、`data/`、PowerShell 脚本不动。

## WP 分解

### WP1 后端拆分:task_service.rs → services/task_service/ 目录模块(纯搬移)

沿用「目录模块 + `use super::*`」零签名改动模式(与上轮 agents/engine、ejs 拆分同款):

| 子模块 | 内容 |
|---|---|
| `mod.rs` | TaskService 结构体、new、常量、CRUD(create/list/get/get_with_subtasks/delete)、usage_total/all_usage_total |
| `db.rs` | row_to_task/row_to_subtask/TASK_COLS/reset_task/set_status/set_plan/set_result/set_error/record_usage/create_subtask/set_subtask_status/list_subtasks |
| `prompt.rs` | task_settings/world_context/inject_text/render_agent_prompt/persona_style/提示词模板 |
| `parse.rs` | parse_plan/salvage_step_objects/non_empty + 8 个既有单测搬移 |
| `executor.rs` | run/stop/generate_text/plan_task/generate_step(_with)/summarize_task(_with)/finalize_run/*_retry/run_task_background |
| `cancel.rs` | NEXT_RUN_TOKEN/register_cancel/signal_cancel/is_current_run/remove_cancel_if/remove_cancel_entry |

验证:`cargo test` 全绿(基线 219)。

### WP2 消重复 + 消 panic

- 泛型重试器 `generate_with_retry(label, initial_max_tokens, attempts, cancel_rx, fut_factory)` 收敛三份同构重试。规则保持:空输出分级(finish_reason=length → max_tokens 翻倍至 65536 上限;否则 temperature=0.7;退避 500ms;300s 总看门狗),行为与报错文案语义不变。
- `list_subtasks` 等 DB 读取路径去 `unwrap`/`expect`,统一 `log_query_failure` 优雅降级。

验证:`cargo test` 全绿。

### WP3 状态枚举化(DB schema 不动)

- Rust:`models/types.rs` 新增 `TaskStatus`(Pending/Planning/Running/Done/Partial/Error/Ended)、`StepStatus`、`SubtaskStatus` 枚举,serde snake_case 字符串映射保持不变(落盘与 API JSON 零变化);`set_status(&str)` 等改收枚举;修 `types.rs:490` 过期注释。
- TS:`api/types.ts` 裸 string 改 union;`taskStatus.ts` 加 exhaustiveness 检查(switch default: never),新增状态编译期报错。

验证:`cargo test` + `npm test -w web` 全绿。

- 新路由 `GET /api/tasks/events`(axum SSE,鉴权复用现有 chat SSE 同款 api_token + client header);`api/routes/misc.rs` 注册。
- 集成测试:broadcast receiver 断言事件序列(planning→running→done)+ HTTP 端点 smoke。

### WP7 提示词管线整合 + 抗多模式提示词混淆设计(本档核心)

**A. 共享模块 `services/prompt_kit.rs`**(纯能力下沉,引擎与任务双侧调用):

- `constant_world_text(entries) -> String`:任务侧 world_context 的「enabled&&constant 过滤 + (position,order,id) 排序 + `[comment]\ncontent` 格式化」抽为纯函数。
- `system_inject_text(cfg: &PromptInjectConfig) -> String`:Simple 合成文本 / Complex 仅 system 楼层(任务侧 inject_text 原样搬入)。
- `render_character_placeholders(prompt, character, world_text, user_goal)` + `TaskPlaceholders { user, last_user_message }` 扩展结构:6 个两侧语义一致的占位符(`{{char}}`/`{{character_name}}`/`{{character_description}}`/`{{personality}}`/`{{scenario}}`/`{{world_info}}`)共享;task 专属 `{{user}}`=「用户」、`{{lastUserMessage}}`=任务目标 经扩展参数传入;无执行者置空语义保留。
- 引擎侧只把字面 replace 段替换为共享函数调用;EJS/触发式/depth/概率/状态块/MacroCtx 全部留在引擎不动。

**B. 类型级模式隔离(抗混淆核心)**:

- `RoleplayPromptConfig(String)`(非空权威)与 `TaskPromptConfig(Option<String>)`(None=内置任务默认)新类型;`RuntimeSettings` 扁平 `agent_system_prompt` 与 ModeSettings 覆盖字段改用新类型(serde 透传保持 settings.json 线格式不变)。
- `for_mode()` 返回类型化 `ModePrompt`;新增 ModeSettings 字段默认「继承」语义,必须显式声明隔离,编译期防漏判。
- `default_task_agent_prompt()` 内聚进同一模块,隔离规则与默认值同处可审。

**C. 任务侧补 untrusted 边界包裹**:

- 引擎 `untrusted_boundary()`(`messages/build.rs:13-23`)移到共享可复用位置;任务侧拼装 persona_style/world_context/inject_text/agent_system_prompt 时逐一包裹 `<UNTRUSTED_PROMPT_SOURCE>`,与引擎防注入水位拉齐。
- 规划器提示词维持「不注入 Agent 提示词与注入文本」不变。

**D. 双向污染测试矩阵(tests/tasks.rs + settings 单测)**:

1. task 执行器/汇总器不含 roleplay 人设词与 `{{char}}` 原文(已有 E2E,保持绿);
2. roleplay 扁平值不受 task 覆盖层影响(`for_mode(Roleplay)` 等于扁平);
3. task 覆盖层字段独立增删不影响 roleplay(读写对称性);
4. task 无执行者时渲染产物不含任何 `{{` 占位符原文泄漏;
5. 新增 ModeSettings 字段默认继承语义的编译期 + 单测锚点。

**E. 设置 UI 抗混淆(用户点名约束)**:

- `AgentSettingsSection.vue`:按 `store.appMode` 在「Agent 系统提示词」字段旁显示模式徽标(任务模式专属/角色扮演专属)+ 一行说明文案「该提示词按模式独立存储,互不影响」;task 模式下「恢复默认」按钮文案明确为「恢复任务模式默认提示词」。
- `genSettings` 的 loadSettings/saveSettings 已按 mode 分流(现状正确),补 store 测试断言 `?mode=` 参数随 appMode 切换。
- 不动存储结构与 API,仅 UI 标注 + 测试。

**F. 文档**:《模式提示词边界.md》——两模式提示词来源/回退规则/注入边界/untrusted 包裹约定,供后续维护防回归。

验证:`cargo test` + `npm test -w web` 全绿;四个污染矩阵用例全绿;`prompt_order_golden_with_untrusted_boundaries` 引擎金样测试原样通过。
