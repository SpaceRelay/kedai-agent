# 子任务终态语义与退出确认弹窗-变更说明(2026-09-16)

> **范围**:`docs/截断与Agent工具面修复计划-2026-09-16.md` 的**批次 4**(子任务 `ended` 二义与
> `finished_at`)与**批次 5**(退出确认改至上主义前端弹窗)。批次 1–3 见该计划的 §1。
>
> **对外契约变化**:① 新增 `finished_at` 列与字段(两张子任务表 + DTO + API + 类型);
> ② `agentend` 不再把已完成任务改写成 `ended`(**行为变更**,见 §3);③ 关闭窗口由
> Tauri 原生对话框改为前端弹窗,新增两个壳事件。

## 1. 批次 4 · 子任务终态语义

### 1.1 要解决的问题

`ended` 一词同时承担两种语义:实跑记录第(3)条中 `dup_name` 完成后被 `agentend` 仍是
`ended` 但保留 `result`,而中途召回的 `team_lifecycle_probe` 同样 `ended` 但 `result` 为空 ——
用 `status === 'done'` 过滤会丢掉「已完成但被结束」的交付物,用 `ended ⇒ 空结果` 又会误判。

**根因**:`AgentSubtaskService::end` 无条件 `set_status(id, "ended")`,把已 `done` 的记录覆盖。

### 1.2 改动点

| # | 改动 | 位置 |
|---|---|---|
| 1 | `end` 对终态幂等:已 `done`/`error` 的记录**不覆盖** status/result,仅补记缺失的 `finished_at` | `services/agent_subtask_service.rs` |
| 2 | `end` 返回显式 `SubtaskEndOutcome`(`Missing`/`Interrupted{prior_status}`/`AlreadyFinished{prior_status}`),替代原 `bool` —— 落实「让返回结构自证」 | 同上 |
| 3 | 进入终态(`done`/`error`/`ended`)时记 `finished_at`,**只记首次**(避免后续写入把完成时刻推后) | 同上 + `services/task_service/db.rs` |
| 4 | 新增幂等迁移 `ensure_agent_subtasks_finished_at_column` 与 `ensure_task_subtasks_finished_at_column`(共用 `add_column_if_missing`),**不动 `SCHEMA_VERSION`** | `migration/ddl.rs` |
| 5 | 迁移三处接线:`Db::open` 升级链、`merge_databases` 基线库侧与源快照侧 | `models/db/mod.rs`、`migration/merge.rs` |
| 6 | 新库建表带该列(`agent_subtasks` 与 `task_subtasks` 表尾) | `models/db/schema.rs` |
| 7 | DTO 增列 + legacy 表 SELECT/INSERT/UPDATE/行映射同步 | `models/types.rs`、`services/task_service/db.rs` |
| 8 | 回显:`read(type=subtask)` 命中体、`todo` 的 subtasks 项各带 `finished_at`;`agentend` 每项新增显式 `outcome` | `tools/agent_tools_read.rs`、`tools/agent_tools_agent.rs` |
| 9 | 前端类型 `TaskSubtask` 增 `finished_at: string` | `web/src/api/types.ts` |

**列序约束**:`finished_at` 必须是两张表的**最后一列**——`ALTER TABLE ADD COLUMN` 只能追加到
表尾,而跨库合并的 schema 比对与迁移元测试都会逐位比对列序。

### 1.3 兼容性变更登记(重要)

**`ended` 的覆盖面收窄**:此前「已完成再被召回」也会落 `ended`;现在它保持 `done`(result 保留),
只有**真正中途中断**才落 `ended`。

- 这正是实跑记录第(3)条的诉求,但属行为变更。
- **受影响的调用方均已核对**:`read(type=subtask)` 的候选过滤 `status != "ended"` 在新语义下
  更正确(被排除的只剩真中断项);`web/src/taskStatus.ts` 的 `ended → 已停止`/红色与
  `AgentPanel.vue` 的 `subtaskDot`/`subtaskCardClass` 无需改动——「完成后再召回」现在渲染为
  完成态,正是期望结果。
- `agentend` 的 `ended` 字段语义不变(仍表示「记录存在且本次调用未报错」);新增的 `outcome`
  才是判语义的推荐字段(`interrupted` / `already_finished` / `missing`)。
  既有 `existed`/`prior_status`/`interrupted` 字段**全部保留**,不做破坏性删改。

### 1.4 验收断言

- `end` 幂等:`done`/`error` 记录调 `end` 后 status 与 result 不变、返回 `AlreadyFinished`;
  不存在的 id 返回 `Missing`;活跃任务返回 `Interrupted` 且 `finished_at` 非空。
- 迁移:两张表各跑一次补列成功、旧行默认 `''`、幂等(重复执行不产生重复列)、表缺失时零列返回
  不报错;迁移后列名与顺序与全新库逐位一致。
- 迁移元测试 `schema_migration_meta` 的逐表指纹比对通过(自动覆盖新增列的**位置**)。
- `read(type=subtask)` 命中体与 `todo` 的 subtasks 项含 `finished_at`;`agentend` 含 `outcome`。
- 契约门禁 `node tools/check-contract.mjs` 通过(Rust 加字段而 TS 漏加必 FAIL)。

## 2. 批次 5 · 退出确认改为至上主义弹窗

### 2.1 要解决的问题

退出确认此前是 **Tauri 原生系统对话框**(`window.dialog()`),外观是 Windows MessageBox,
**不受前端 CSS 影响**,做不出应用统一的至上主义/构成主义语言。
附带问题:Android 返回键无处可退时**直接退出、无确认**,误触即丢未保存内容,两平台语义不一致(桌面要确认、Android 不确认)。

### 2.2 改动点

| # | 改动 | 位置 |
|---|---|---|
| 1 | 去掉原生 `window.dialog()`,改 `api.prevent_close()` + `emit("kedai://close-requested")` | `src-tauri/src/lib.rs` |
| 2 | **二次关闭兜底**:`ExitGuard(AtomicBool)` 托管状态,第二次 `CloseRequested` 直接退出 | 同上 |
| 3 | 统一退出出口 `exit_now()`:先清端口残留再 `exit(0)`,`kedai://exit-app` 回调复用 | 同上 |
| 4 | 新增 `kedai://close-cancelled` 事件:前端取消时复位兜底标记 | 同上 + `web/src/components/ExitConfirmModal.vue` |
| 5 | 注册弹窗 `exitConfirmOpen`(声明在**末尾** = 叠在最上层) | `web/src/modals.ts`、`stores/uiPrefs.ts` |
| 6 | 监听 `kedai://close-requested` 打开弹窗;`onUnmounted` 注销 | `web/src/App.vue` |
| 7 | Android 返回键无处可退时改开同一弹窗(不再直接退出) | `web/src/App.vue::handleAndroidBack` |
| 8 | 新增至上主义弹窗组件 | `web/src/components/ExitConfirmModal.vue`(新建) |

**无需改 `capabilities/default.json`**:已核实生成的 `acl-manifests.json` 中
`core:default → core:event:default = [allow-listen, allow-unlisten, allow-emit, allow-emit-to]`,
Rust→前端下发事件与前端取消事件都不需要追加权限。

### 2.3 对计划文档的两处修正(实施中发现文档与实际不符)

计划 §3.3 第 5.3 项称「端口清理保持在 `kedai://exit-app` 回调(已存在),确认路径复用」——
**实际不成立**:`kedai://exit-app` 的事件回调此前只调 `handle.exit(0)`,**没有**端口清理,
只有原生对话框的 confirmed 回调清理。本次以 `exit_now()` 统一两个出口,顺手补上这个缺口
(即「点退出后 kedai-server 仍在跑」这一类残留的一个来源)。

计划未列的**必要补充**:仅有二次关闭兜底是不够的——用户在确认框点「取消」后,兜底标记仍是
置位态,下一次单击关闭会**直接退出**(跳过确认)。故新增 `kedai://close-cancelled` 事件复位标记;
该行为有单测锁定(`close_request_guard_forces_exit_only_on_second_request`)。

### 2.4 验收断言

- 桌面:点窗口关闭 → 出至上主义弹窗(非系统对话框);「取消」窗口不关且**下一次关闭仍弹确认**;
  「退出」进程结束且端口清理执行。
- 兜底:前端不响应(页面未加载完/弹窗 chunk 加载失败)时,第二次点关闭直接退出。
- Android:返回键无处可退 → 出同一弹窗;取消则留在应用。
- 弹窗三态通知有组件测试覆盖(取消 → `close-cancelled`、退出 → `exit-app`、遮罩点击等同取消)。
- 注册表元测试 `modals.test.ts` 自动派生通过(flag 无重复 / uiPrefs 双向 / App.vue v-for)。
- `node tools/check-arch.mjs` 通过(弹窗白名单由 `modals.ts` 派生,新增弹窗零改动)。

## 4. 风险与回滚

- **回滚代价低**:批次 4 是 `ALTER TABLE ADD COLUMN` + 只增字段,回滚只需还原代码,新增列留在
  旧库无害(旧代码不读该列);批次 5 是纯替换,还原 `lib.rs` 即回到原生对话框,前端新增文件删除、
  注册表两处回退。
- **残余风险**:`ended` 语义收窄对未知第三方消费方是行为变更(仓内消费点已全部核对,见 §1.3)。
- **有意不做**(沿用计划 §5):不加「达到 max_tokens 自动续写」;不改 generate-raw 默认预算与
  32768 自愈;不实现 `todo` 汇总位数;不动 `docs/archive/`;不细分 `error`;不在前端 UI 展示
  `finished_at`(本轮只做后端回显与类型对齐)。
