# 架构收口五项(M0~M5)变更说明 — 2026-09-13

> 对外变更契约。本轮针对架构评审报告识别的「未收口」债务落地,以**不改变任何
> API 线格式与 DB schema** 为前提。全部批次结束门禁:`tools/check-all.ps1` 8 个
> stage 全绿(含本轮新增 2 个 stage);后端 923 测试、前端 697 测试全过。

## 一、任务事件分类类型化(M0)

- **新增** `models/types.rs::TaskEventKind` 枚举(10 变体,`#[serde(rename_all = "snake_case")]`);
  `SseEvent::Task.kind` 由 `Option<String>` 改为 `Option<TaskEventKind>`。
- **收益**:后端拼错分类名从前只在前端静默失效(未知 kind 不刷新),现由编译器拦住;
  19 处发射点漏改即编译错误,天然全覆盖。
- **线格式保证**:与字符串时代**逐字节一致**。守卫证据:`models/types.rs` 的 5 个
  serde 快照测试与 `tests/task_events.rs` 的 literal kind 断言**均未修改**即通过。
- **前端**:`TaskEventKind` union 无需改动(已对齐),仅补注释指向 Rust 真源。

## 二、版本单源(M1)

- 修复真实漂移:`package-lock.json` 停在 **0.2.0**,其余 6 处声明为 0.2.1。
- `tools/bump-version.ps1` 纳入 `package-lock.json`(顶层 + `packages[""]` 两处,不碰依赖版本)。
- `build.ps1` 开头新增 `Assert-VersionConsistency`:校验 7 处声明一致,不一致即
  `throw` 并列出差异(已实测通过/失败两条路径)。

## 三、契约快照校验(M2)

- **新增** `tools/check-contract.mjs`(纯 Node 零依赖,对齐 `perf-baseline.mjs` 风格):
  按显式映射表比对 Rust 结构体/枚举与前端手写类型的字段集合,检出
  「后端有前端无」「前端有后端无」两类漂移,非空即 `exit 1`。
- 首版覆盖 9 组高变更面(记忆条目/蒸馏结果/任务记录/步骤/子任务/调用记录 +
  三个枚举)。已实测能抓到 `DistillResult.skipped` 缺失这类真实漂移。
- 纳入 `check-all.ps1`(`npm run check:contract`)。

## 四、任务执行路径收口(M3,本轮最重)

此前存在**三套并行执行路径**:legacy(if-match 直调)、六模式(ModeExecutor)、
followup(直调 `solo::run_agent_loop` 绕过接口)。现全部上 `ModeExecutor` 缝:

- **新增** `task_engine/legacy.rs`:`LegacyExecutor`,原 `run_task_background` 机械搬迁
  (三段式、步骤无工具、subtask 落 `task_subtasks` 表、phase=plan/step/summary 全保留)。
- **新增** `task_engine/followup.rs`:`FollowupExecutor`,原 `run_followup_background` 搬迁。
- **新增** `OnSuccess::SelfFinalized`:`legacy`/`followup` 的收尾语义与六模式不同
  (legacy 中途失败即自行 `finalize_run`、成功自行写 result;followup 的 result 与
  消息文本分离),若强行走引擎统一收尾会**双重写入**。该变体明确划界:引擎不再写库。
- `TaskService::run` 的 if-match 塌缩为单一派发;`TaskRunContext` 增 `token` 字段供
  自行收尾者做 `is_current_run` 守门。
- **行为不变判据**:`tests/tasks.rs` 50 用例(含 `task_legacy_subtasks_still_from_db`、
  `task_followup_keeps_partial_status`)、`tests/task_events.rs` 8 用例**零改动通过**;
  并已用构建产物做运行期冒烟(legacy 三段式 status=done、2 个 subtask 落 DB、plan 2 步)。
- **默认模式保持 legacy 不变**(产品决策未变)。

## 五、重复实现收敛(M4)

- **截断自愈留痕**:`solo.rs` 与 `custom.rs` 两段逐行同构的循环收敛为
  `TaskService::record_self_heals`(补落被截断行 + 补 usage)。
- **执行者 system 提示词组装**:`generate_step_with` 与 `run_agent_loop` 两份同序实现
  收敛为 `TaskService::assemble_executor_system_prompt`。
- **AppState 归组**:24 个扁平静态字段拆为 `CoreServices`(核心服务)+
  `ConcurrencyGuards`(并发/限流脚手架),`AppState` 经 `Deref` 透出——205 处
  `state.db` / `state.sessions` 等既有访问路径**零改动**,仅 4 处锁字段改
  `state.guards.*`。

## 六、前端架构护栏(M5)

- **新增** `tools/check-arch.mjs`:① store 循环依赖检测(DFS 找环);
  ② `.vue` 中直改 store state 检测(白名单按「是否已有 action」精确分类)。
  纳入 `check-all.ps1`(`npm run check:arch`)。
- **断环**:五个 store(character/chat/genSettings/uiPrefs/task)原构成**一个强连通
  分量**,现经 `stores/storeBridge.ts`(回调注册,状态仍住各 store 的 setup 内以保
  Pinia 实例隔离)拆为单向 DAG,**0 环**。
- **修 5 处真绕过 action 的赋值**:`ChatTopbar.vue`(2 处 renderHtml)、
  `settings/UiSection.vue`(agentPanelOpen、renderHtml)、`DevToolsModal.vue`(eventLog);
  新增 action `uiPrefs.setRenderHtml/toggleRenderHtml`、`chat.clearEventLog/setAgentMode`。
  另修复 `App.vue` 收起抽屉时漏记抑制标记的缺陷(直改 agentPanelOpen → 走 collapseAgentPanel)。
- **沙箱评估结论**(登记为 `known-limitations.md` L11):`event.origin` 在不透明源下恒为
  `"null"`、`event.source` 被 WebView2 包装,**两者均不可用**;`allow-modals` 有真实
  角色卡依赖(赛马娘卡 alert 链路),保留。nonce 仍是主防线,不构成现实漏洞。
- **补 3 个大组件测试**(jsdom + @vue/test-utils):`TaskBoard`(4)、`PromptManager`(3)、
  `WorldBooksModal`(4),覆盖空态/渲染/mode 徽标/主操作入口/关闭动作。
