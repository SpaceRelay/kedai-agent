## 1. 结论先行:不是数据问题,是窄屏 CSS 塌缩

用户看到「数字输入框空白」直觉会怀疑「值没保存/加载失败」。实测与代码双向确认**值一直都在**:

- 后端 `RuntimeSettings`(`services/settings_service/mod.rs:145-219`)里这些字段全是
  **非 Option 的 `u32`** 且带 serde 默认值,`GET /api/settings` 逐字段原样输出数字,不可能为 null。
- 前端 `stores/genSettings.ts:104-154` 的 `loadSettings` 对**全部**数值字段做了 `?? 默认值`
  (`??` 同时拦 null 与 undefined),写入 store 的永远是非空数字。
- 实机 DOM 快照实测:`spinbutton "…默认 32"` 值为 `"64"`、`"4"`、`"16384"` —— 数据在,只是**看不见**。

空白是**纯 CSS 塌缩**,机制:

```
.sv-inp-row            display:flex(单行,无 wrap)
.sv-input/.sv-select   flex:1  ⇒ flex-basis:0%
.sv-note(长中文说明)   flex-basis:auto(默认)
```

负自由空间下,flex 收缩量按 basis 比例摊派:说明文字的 basis 很大 → 吃掉全部收缩量;
而 basis 为 0 的输入框**既不缩也长不大**,最终只剩自身 `padding 12px×2 + border 3px×2 ≈ 30px`,
内容盒宽度 0,**数值被裁成空白框**。`.inject-num { width:110px }` 同样被 `flex-basis:0%` 覆盖而失效。

这解释了那个反直觉现象:**说明文字越长的行越空白**——「子代理深度(1-4,默认 2)」「子代理并发
(1-16,默认 6)」说明最短,只有它们幸存能显示 2 和 6。

`执行流程` 面板是另一个同源问题:`.flow-row` 是 6 列 `auto` grid,最小内容宽合计约 350px >
可用约 282px,行盒溢出;`.sv-hub-content` 的 `overflow-y:auto` 使另一轴计算为 `auto` → 出现横向
滚动,最右列的 ✕ 被推出视口;grid 轨道压到 min-content → 下拉只剩箭头、无 `nowrap` 的中文按钮
缩成 1 字宽(「生成」竖排)。`.floor-row`(7 列 grid)同病。

移动端媒体查询(`@media (max-width:767px)`,原 3734-4031 行)对这些选择器**零规则**,
即从未做过窄屏适配;`.flow-select-wide` 还是个全仓悬空类(组件用了 4 处但没有任何 CSS 定义)。

## 2. 修复

### `web/src/style.css`

**移动端新增一节**(`@media (max-width:767px)` 内,`.sv-hub-modal` 之后):把表单行改成
「标签与控件同一行(控件吃满剩余宽)+ 说明文字独占下一行」,步骤行/楼层行由 grid 改 `flex-wrap`。

| 规则 | 作用 |
|---|---|
| `.sv-inp-row { flex-wrap:wrap; row-gap:6px }` | 允许换行,是后续所有布局的前提 |
| `.sv-inp-row > .sv-note { flex:1 1 100% }` | 说明换行独占,消除与控件抢空间 |
| `.sv-inp-row > .sv-input/.sv-select { flex:1 1 0; width:auto; min-width:120px; min-height:44px }` | 控件吃满剩余宽;`min-width` 既兜住 0 宽塌缩,又是折行阈值;44px 满足既有触摸目标下限 |
| `.flow-row` / `.floor-row` 改 `flex-wrap` + 子项 `flex` | 消除横向溢出与 min-content 压缩 |
| `.sv-btn:not(.sv-btn-fill) { white-space:nowrap }` | 修「生成」竖排 |
| `> .floor-actions { margin-left:auto }` | 操作按钮推到自己那行右端(原在最右列被挤出视口) |
| `.sv-inp-row > .flow-lib-actions { flex:1 1 100%; display:flex; justify-content:flex-end }` | 流程库按钮组换行右对齐,给「当前流程」下拉让出整行 |
| `.sv-inp-row > .flow-meta-pair { flex:1 1 100%; display:flex; flex-wrap:wrap }` | 「流程名称/说明」各自成行,避免「说明」标签孤立 |

**全局新增两条桌面中性规则**(不在媒体查询内,靠 `display:contents` 保证桌面逐像素不变):

```css
.flow-lib-actions { display: contents; }   /* 桌面:子按钮仍是 .sv-inp-row 直接 flex 项 */
.flow-meta-pair   { display: contents; }   /* 同上:四个子元素仍是直接 flex 项 */
.flow-meta-gap    { padding-top: 8px; }    /* 复刻原内联 style 的桌面效果 */
```

`display:contents` 让包装元素自身不生成盒子、子元素直接参与上层 flex 布局 —— 因此桌面端
`.flow-row` 仍是 6 列 grid(实测 `gridTemplateColumns` 与改动前一致、所有子项 top 相同)、
`.sv-inp-row` 仍是单行。

### `web/src/components/settings/AgentFlowSection.vue`

- 「当前流程」的 3 个按钮包一层 `<span class="flow-lib-actions">`(桌面靠上面那条
  `display:contents` 保持原样)。**必要性**:仅靠 `min-width` 无法让 3 个按钮整齐换行
  (flex 贪心只把第 3 个挤下去),成组后窄屏可整体移到下一行。
- 「流程名称 / 说明」各包一层 `.flow-meta-pair`;原内联 `style="padding-top:8px"` 换成
  `.flow-meta-gap` 类,便于窄屏用更高特异性归零而无需 `!important`。

### `web/src/components/settings/GenParamsSection.vue`

删除 `onMounted` 里 3 行冗余兜底(`maxToolRounds/toolHistoryKeepRounds/toolHistoryBudgetTokens` 的 `??`),
连同已不再使用的 `onMounted` import。`stores/genSettings.ts` 已对全部字段集中兜底,组件级只兜 3 个
既多余又误导(让人以为另 8 个字段缺默认值),且它掩盖了真实问题(样式)。

## 4. 已知限制与未做

- **仅修窄视口布局,未重做信息架构**:字段分组、文案、控件类型一律不动。

  它们共享同一「长说明挤窄控件」问题,本次一并修好,属收益;全部规则锁在
  `max-width:767px` 内,桌面不受影响。
- **未动** `.sv-btn-square`(18 个组件复用)/ `.sv-btn-row`(7 个)的既有定义。
- **面板因此在手机上变高**(说明文字各占一行),滚动变长是预期代价;换来的是输入框
  可辨、可点、不塌缩。
- 提示词注入面板的「楼层系统」需切到「复杂」模式并至少有一条楼层才可见;已在实测中
  新造一条楼层验证。
