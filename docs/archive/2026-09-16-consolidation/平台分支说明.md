# 平台分支说明(主干 + 平台分支)

> 状态:**生效中**(2026-09-13 建立)。
> 适用读者:开发 agent 与维护者。禁止注入聊天模型。
> 本文是分支模型的单一事实来源:改分支策略、新增平台专属目录时同步更新。

## 一、为什么是同源,而不是两套代码

Kedai 是**单一代码库、两个交付平台**:Rust 后端(`server-rs/`)、Vue 前端(`web/`)与
共享工具链在两端完全复用,只有平台能力层与打包发布层不同。平台差异用编译期与运行期
开关隔离,而非复制代码:

- **Rust 侧**:`#[cfg(target_os = "android")]` / `#[cfg(not(target_os = "android"))]`
  门控平台模块。例:`server-rs/src/services/exec/mod.rs:144-148` 桌面走 `desktop.rs`、
  Android 走 `android.rs`;`server-rs/src/services/mod.rs:16-25` 的 `keystore_android` /
  `jni_bridge` / `native_bridge_android` 仅 android 目标编译。
- **前端侧**:`web/src/platform` 的 `isAndroidTauri` 运行期判据。例
  `web/src/components/settings/AndroidExecSection.vue:54` 用
  `showAndroidTiers = isAndroidTauri` 决定 ROOT/Shizuku 等级条是否显示,
  桌面端自动隐藏但**文件仍在共享树中**。

**结论:平台专属文件必须留在主干。** 它们要么被共享代码 import(如
`AndroidExecSection.vue` 被共享的 `AgentSettingsSection.vue:11` 引入),要么被共享脚本
引用(如 `build.ps1`、`tools/bump-version.ps1`、`tools/check-lock-sync.mjs` 都读
`launcher/`)。把它们从主干剥离会直接打断主干构建与 CI,而不是"清理"。

## 二、分支拓扑

```text
main ────────────── 主干:全量共享代码 + cfg/运行期门控的平台代码
  ├── kedai-Win      平台分支 = main + Windows 发布清单(平台发布元数据)
  └── kedai-Android  平台分支 = main + Android 发布清单(平台发布元数据)
```

三个分支**源码逐字节相同**;平台分支只在各自的发布清单文档上分叉。这不是"没分成",
而是"代码本来就同源,强行切成两份反而制造双向 cherry-pick 漂移"。

## 三、三条规则

1. **共享改动一律落 `main`。** 后端逻辑、前端组件、协议、共享工具链的任何改动先在
   `main` 提交并通过门禁(`tools/check-all.ps1` / CI),再向下游平台分支合并。
2. **平台专属改动落平台分支。** 指打包配置、签名、发布清单、平台限定文档。若某改动
   同时影响两侧(如 `tauri.conf.json` 的版本号),在 `main` 改,由平台分支合并吸收。
3. **合并方向:`main` → 平台分支。** 平台分支不向 `main` 反向合并平台发布元数据
   (避免两份清单在主干预架);确需回流共享逻辑时,先在平台分支验证,再手动摘取到 `main`。

## 四、文件归属映射

### Windows 专属(打包/启动链)

| 路径 | 说明 |
|---|---|
| `launcher/`(Cargo.toml / Cargo.lock / src/main.rs) | 图形启动器,产物即用户双击的 `Kedai.exe`(零第三方依赖) |
| `build.ps1`、`start.ps1` | Windows 构建与启动脚本(便携版 / NSIS / 构建指纹) |
| `tools/build-portable.ps1`、`tools/bump-version.ps1`、`tools/Write-BuildStamp.ps1`、`tools/cargo-vcvars.cmd`、`tools/make-icons.ps1` | Windows 打包与版本工具 |
| `src-tauri/tauri.conf.json`、`src-tauri/capabilities/default.json`、`src-tauri/icons/*` | 桌面壳配置与图标 |

> `launcher/` 是**共享工具链的依赖**(见 §一),虽为 Windows 专属能力,仍留在 `main`。

### Android 专属(打包/桥接链)

| 路径 | 说明 |
|---|---|
| `src-tauri/gen/android/**` | Gradle 工程、Kotlin 桥(`KeystoreBridge` / `ShellExecutorBridge` / `KeepAliveService` 等)、图标与资源 |
| `server-rs/src/services/keystore_android.rs`、`native_bridge_android.rs`、`exec/android.rs` | android 目标专编:Rust 抽象层只做字符串进出,Java 能力经 Kotlin 桥 |
| `web/src/components/settings/AndroidExecSection.vue`(+`.test.ts`) | 命令执行授权面板;桌面端由 `isAndroidTauri` 运行期隐藏 |
| `tools/make-android-icons.ps1` | Android 图标生成 |
| `docs/android-port-plan.md`、`docs/命令执行层与Android三档执行器-变更说明.md` | Android 移植与执行层文档 |

### 共享(改动落 `main`)

`server-rs/src/**`(上列 android 模块除外)、`web/src/**`(上列 AndroidExecSection 除外)、
`docs/**` 绝大多数、`tools/check-*.mjs`、`tools/check-all.ps1`、`tools/hooks/pre-push`、
`.github/workflows/ci.yml`。

## 五、构建与发布入口

| 平台 | 入口 | 详见 |
|---|---|---|
| Windows | `.\build.ps1`(完整:前端 + release + 便携版 + 指纹);`-TestOnly` 仅测试版 | `MAINTENANCE.md` §4;发布清单 `docs/发布检查清单-kedai-Win.md`(**仅在 `kedai-Win` 分支**) |
| Android | `D:\kedai-android\bin\ata.bat android build --apk --target aarch64` | `docs/android-port-plan.md` §五之六;发布清单 `docs/发布检查清单-kedai-Android.md`(**仅在 `kedai-Android` 分支**) |

> 两份发布清单刻意只存在于各自的平台分支——它们是"平台分支相对主干的分叉内容",
> 也是本模型下 `main` 与平台分支的唯一差异。主干上按文件名引用而不用链接,避免悬空。

## 六、同步工作流(常用命令)

```bash
# 1) 共享改动:在主干开发并过门禁
git checkout main
# ... 改代码 ...
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-all.ps1
git commit

# 2) 把主干同步到两个平台分支(线性快进,不产生合并提交)
git checkout kedai-Win     && git merge --ff-only main
git checkout kedai-Android && git merge --ff-only main

# 3) 平台专属改动:直接在对应平台分支提交(如更新发布清单)
```

> 若平台分支已领先(`main` 之后有自己的提交),第 2 步改用
> `git rebase main` 保持线性;平台发布清单是独立文件,不会与主干冲突。

## 七、备份与回滚

建立本模型前,两个旧分支的历史锚点已打 tag 固化,任何操作可回退:

| tag | 指向 | 说明 |
|---|---|---|
| `backup/kedai-Win-0.2.1-b361fee` | `b361fee` | 旧 `kedai-Win`(改名自 `master`)末端,0.2.1 |
| `backup/kedai-Android-0.3.0-beta-b4bd12e` | `b4bd12e` | 旧 `kedai-Android`(改名自 `kedaiAndroid`)末端,0.3.0-A-beta,后成为主干起点 |

回滚示例:`git branch -f kedai-Win backup/kedai-Win-0.2.1-b361fee`。
