## 一、5.1 storeBridge 类型化注册(`web/src/stores/storeBridge.ts`)

**现状**:六条桥(characterId / settingsSaver / settingsLoader / renderHtmlDefault / chatEvent / uiPrefs)
是模块级可变函数指针,无 owner 归属、无测试;`genSettings.ts` 头部注释称「appMode 读回调桥」,实际是顶层
`import { useTaskStore }` 直读(storeBridge 里根本没有 appMode 桥)。

**改动**:

- 六条桥统一由 `createBridge<T>(name, fallback)` 构造为 `StoreBridge<T>`(`register(owner, fn)` + `get()`),
  集中在 `export const storeBridges` 一处登记 owner 与降级行为。
- `register` 的 **owner 必填**:同一 owner 重复注册 = 幂等覆盖(store 重建实例等正常场景);
  不同 owner 抢同一桥 = `console.warn` 诊断(含桥名与两个 owner),不再静默覆盖。
- 未注册时 `get()` 返回**显式降级实现**,与断环前各调用点旧行为一一对应:characterId→`null`、
  settingsSaver→reject(调用方走既有「保存失败回滚」分支)、settingsLoader/renderHtmlDefault/chatEvent→no-op、
  uiPrefs→安全空实现(`isCallTraceOpen` 恒 false)。
- 12 个原导出名与签名**全部保留**(一行包装转发,owner 在包装处固定),调用点零改动。
- 保留「不把状态提为模块级 ref」的 Pinia 实例隔离纪律说明。

**注释-实现校正**(逐条 grep 核实):`genSettings.ts`(改为「appMode 顶层 import useTaskStore 直读,
该边单向、storeBridge 无 appMode 桥」)、`task.ts`(原文「appMode 经回调桥暴露给 genSettings」与事实相反)、
`uiPrefs.ts`(改为准确描述反向注册的两个 sink);`chat.ts`、`character.ts` 的桥注释核实属实,未改。

**测试**(`web/src/stores/storeBridge.test.ts`,14 例):每桥「注册取值 / 未注册降级」配对 12 例
(含 settingsSaver 的 reject 语义与 uiPrefs 空实现不崩)+ owner 诊断 2 例(同 owner 幂等不告警、
异 owner 告警且以后者为准)。

## 二、5.2 弹窗 MODAL_FLAGS 单点定义

**现状**:新增/重命名一个弹窗要同步五处——uiPrefs 声明 + store 门面 + App.vue 模板 v-if +
App.vue 本地 `MODAL_FLAGS` + check-arch 白名单;且 check-arch 白名单里 `devToolsOpen` 是僵尸项(全仓无此标志)。

**改动**:

1. 新增单一事实来源 `web/src/modals.ts`:`MODALS` 注册表(14 条,`modal(flag, label, loader)` 单行声明,
   **声明顺序 = 渲染顺序**,后声明者叠在上层)+ `ModalFlag` 字面量联合 + `MODAL_FLAGS`。
2. `App.vue`:14 段手写 `lazyModal` 常量与 14 段 `<Transition><组件 v-if>` 全部删除,改为
   `<Transition v-for="modal in MODALS" :key="modal.flag"><component :is="modal.component" v-if="isModalOpen(modal.flag)" />`;
   `retryModalLoad` 与返回键共用收口后的 `storeFlags` 访问。
3. Android 返回键遍历改为**按渲染逆序**(先关最上层)。**语义修正说明**:旧实现按手抄数组顺序
   (settingsOpen 打头)关,与同函数「关掉最上层的那个」注释相反;现渲染下同屏最多一个弹窗
   (各入口开面板即关 Hub),该差异实操不可达,属向文档语义对齐。
4. `tools/check-arch.mjs`「组件直改 state」白名单的弹窗部分**由 `modals.ts` 解析派生**
   (契约:单行 `modal('flag', 'label', () => import(`);文件缺失/结构未识别/解析 0 条/flag 重复
   一律**显式 FAIL**,不静默变空;已实测改写结构后确实报 FAIL)。僵尸项 `devToolsOpen` 删除。
5. `SettingsHub.vue` 的 `openPanel` 参数类型从手抄 13-flag 联合改为 `import type { ModalFlag }`
   (brief 之外的第 6 处同步点,顺手收敛)。

**效果**:新增一个弹窗 = **2 处**(`modals.ts` 加一条 + `uiPrefs.ts` 加 ref);渲染、返回键、
check-arch 白名单、设置 Hub 类型全自动。

**测试**(`web/src/modals.test.ts`,9 例):注册表自身(flag 无重复 / label 非空且无首尾空白 /
组件已定义 / `MODAL_FLAGS` 与声明顺序对应);registry ↔ uiPrefs **双向相等**(源码解析 + 运行期键检查,
任一方向漏改必红);App.vue 必须由注册表 v-for 派生、返回键取 `MODAL_FLAGS`、不得残留按 flag 硬编码的
`v-if="store.<flag>"`。
