# 第一篇:底层架构与功能实现详解

## 第 1 章 总览:进程模型与组件契约

Kedai 是本地运行的 AI 角色扮演/文学创作工具,兼容 SillyTavern 生态(角色卡 V2/V3、世界书、正则脚本、mvu/EJS 变量系统),内置「计划→执行→反思」Agent 引擎与六模式任务引擎,数据全部存本地 SQLite(WAL)。

**四个可执行单元**:

| 组件 | 技术栈 | 规模 | 职责 |
|---|---|---|---|
| `server-rs/` | Rust + axum 0.8 + tokio 1 + rusqlite 0.40(M1 已升级,原基线 0.32) | 176 文件 / 58,674 行 + 11,017 行集成测试(18 文件) | 核心:API、Agent 引擎、解析层、沙箱、MCP 客户端;`include_dir!` 编译期内嵌 `web/dist`,单二进制兼作静态资源服务 |
| `web/` | Vue 3.5 + Pinia 2.3 + Vite 6 + Tailwind v4 + TS strict | 163 文件 / 28,734 行 + 53 个测试文件 | 前端;开发时 Vite dev(5173)代理 `/api`→3001,生产被内嵌 |
| `src-tauri/` | Tauri 2 | ~400 行薄壳 | 桌面壳,与后端**同进程**调 `run_server`;数据/日志重定向 `%APPDATA%\com.kedai.app\`;`/api/health` 就绪后才显示窗口 |
| `launcher/` → 根 `Kedai.exe` | 零依赖 Rust/Win32(仅 std + user32/shell32) | 896 行 | 图形启动器:过期/指纹漂移检测 → 必要时触发 `build.ps1` → 拉起便携版后退出 |

**硬契约**:
- 监听 `127.0.0.1:3001`;非 loopback 需 `KEDAI_ALLOW_REMOTE=1` + ≥32 字符固定 token(`server-rs/src/lib.rs:77-82`)。
- 除 `/api/health` 外全部要求 Bearer token(每次启动随机 256-bit,或 `KEDAI_API_TOKEN` 固定);前端经 `/api/bootstrap`(仅 loopback)领取。
- 测试版 `dist\kedai-server.exe` 与便携版 `dist\Kedai-portable\Kedai.exe` 为两条独立编译链,各冻结编译时刻的 `web/dist`;`build.ps1` 双端同步产出并写 `<exe>.build.json` 指纹(`version/build_time/dist_hash`),启动器与 `start.ps1` 比对指纹,不一致自动重建。两版共用 3001 与同一数据目录,不可同时运行。

**数据流**:`浏览器/WebView → /api/xxx → api/routes(五域:chat/settings/agent/content/misc)→ services → SQLite`;生成链路经 `connectors`(openai-compatible/mock)→ LLM → SSE 流回推(token/step/tool_call/tool_result/vars/finish)。任务引擎 DB 写入后经期 broadcast 通道发 `SseEvent::Task`,`GET /api/tasks/events` 转 SSE,前端事件驱动刷新无轮询。

**数据目录现状**:2026-09-05 已统一到 `%APPDATA%\com.kedai.app\`;仓库内 `data/` 已退役为 `data.retired-20260905/`(499K),双备份在 `backups/`(13M),处置方案见附录 B。

## 第 3 章 上下文装配管线与世界书匹配

**collect_context → finalize_messages 顺序**(函数级):
1. 阻塞池读角色卡、历史消息、压缩摘要;2. 历史投影(重生成 swipes 取当前版本)+ snip;3. 世界书条目收集/分离/分组/渲染;4. mvu 状态块生成;5. 产出只读 `CollectedCtx`;6. `build_llm_messages_with_position` 六层拼装(系统提示/世界书常态位/注入/历史/GENERATE 位/@INJECT);7. 运行时主提示词前置、摘要槽/记忆槽插入;8. `trim_to_context` 按预算裁剪;9. 发送统计落宏变量(供模板读取)。

**世界书匹配算法**(`agents/engine/worldbook.rs:56-166`):
- **扫描池**:只取 `role=="user"` 的历史消息(`worldbook.rs:69-73`;assistant 文本不触发,测试 `worldbook.rs:441-451`)。
- **逐条目**:disabled 跳过 → 先执行 `@@` 装饰器(`@@if/@@unless` 用 EJS 白名单求值,失败容错为照常注入;`@@var/@@set` 解析存 `decorators`)→ `constant` 恒注入。
- **非 constant**:按条目 `depth` 截最近 N 条用户消息(0/负=全部);**正则优先**(use_regex 且编译成功),否则 keys + keys_secondary 并列子串匹配(大小写按 case_sensitive)。
- **概率门控**:use_probability 时 `simple_roll()`(纳秒 %100)< probability 才注入。
- **注入位置**:`WorldText{constant, triggered}` 两组——常态→位置 3(并入 system;显式 role 则作独立消息);激发→位置 1(默认追加最新 user 消息尾部,**前缀缓存友好**;role=assistant 作独立消息;role=system 钳制为 user)。落点组装在 `messages/build.rs:253-304`。
- **有意裁剪(兼容子集,勿当 bug)**:`sticky/cooldown` 已解析保留但**不参与匹配**;无 ST 式递归激活(recursive scanning)。
- 每条命中 content 过一遍 EJS 渲染(`render_assistant_content_with`),渲染为空不注入。

`WorldEntry` 数据结构(`parsing/world_book.rs:11-65`):keys/keys_secondary/regex/use_regex/constant/enabled/position/depth(缺省 4)/order(缺省 100)/case_sensitive/sticky/cooldown/probability/use_probability/role/decorators;兼容 camelCase(ST)与 snake_case(角色卡)双字段名;`disable`/`enabled` 互反映射(`world_book.rs:315-321`);排序 `position → order → id` 稳定升序(`world_book.rs:253-258`)。

## 第 4 章 缓存感知压缩(compaction)

- **触发**(`mod.rs:1032-1137 maybe_compact`):auto 模式、历史 token ≥ 上下文窗口 × 阈值档位(settings 可调)时,在 plan 之后、collect_context 之前执行。
- **策略**:增量摘要——以既有 `session_compactions` 摘要为基线,只对新增历史段做 LLM 摘要并落库(表 `session_compactions`,schema.rs:231),后续回合以「摘要 + 近期原文」形态进入装配管线(摘要槽在 finalize_messages 第 3 步插入)。
- **缓存感知**:请求快照表 `llm_requests`(schema.rs:240)记录 `prompt_cache_hit/miss_tokens`(连接器侧双风格解析,见第 11 章),压缩决策与发送统计据此感知 provider 前缀缓存命中情况,避免为省 token 反而打断缓存前缀。
- **裁剪兜底**:压缩后仍超预算时 `trim_to_context` 从最早历史向前裁剪,系统层与世界书常态层不动。

## 第 5 章 工具循环与权限闸门

**run_tool_loop**(`agents/engine/executor.rs:386-791`,agent/custom 模式专用):
1. 生成 → 响应含 tool_calls 则进入裁决 `decide_with_policy`;2. 按风险分组:**Safe 级并发执行**,其余**串行**执行且含最长 300s 的用户授权等待(SSE `tool_authorization_required` 事件驱动前端授权卡);3. 回填 assistant(tool_calls)+ tool 结果消息;4. 再生成,直到无 tool_calls 或达 `max_tool_rounds`(默认 32)。
**权限层**(`tools/permissions.rs`):配置持久化 `tool_permissions.json`(tmp 文件 + Windows `ReplaceFileW` 原子替换,`permissions.rs:272-300`);**未知工具默认按 Dangerous 处理**——MCP 工具注册名 `mcp_{server}_{tool}` 不命中任何内建分类,自动被此规则全覆盖。
**多步熔断**(`contracts/multi_step.rs`):FNV 风格 op_hash/failure_hash,近 8 步环形缓冲内同一哈希出现 ≥3 次判 `loop_broken`,防工具调用死循环。

## 第 6 章 任务引擎:六模式与团队编排

**模式对照**(实现:`src/services/task_engine/` 9 文件;服务层:`src/services/task_service/` 7 文件):任务引擎是与角色扮演平级的第二顶层模式(`appMode`),六模式共享同一 `AgentEngine` 工具循环与连接器读锁,差异在计划形态与执行编排。六模式枚举与执行策略详见 `docs/任务引擎六模式.md`(协议锁定文档);`team.rs`(1017 行)实现多子代理团队编排:任务拆分 → 子任务并发/串行调度 → 结果汇总。
**存储六件套**(schema.rs):`tasks`(task_mode 列)、`task_subtasks`、`task_usage`(token 口径)、`task_llm_calls`(含 finish_reason 可观测性)、`task_messages`、`agent_subtasks`,均 `task_id` 外键 CASCADE。
**事件链**:任务引擎 DB 写入 → broadcast 通道 `SseEvent::Task` → `GET /api/tasks/events` 转 SSE → 前端 task store 分发(见第 15 章)。
**与聊天路径的差异**:任务模式跳过 `llm_requests` 落库(FK 指向 sessions,`executor.rs:122`),也**不接契约系统**(见第 9 章)。

## 第 7 章 三层 JS 能力分级(横切设计亮点)

项目对「用户/卡片作者提供的可执行内容」按信任度分三层,**全部刻意回避 eval 与任意代码执行**:

| 层 | 载体 | 实现 | 能力边界 | 资源限制 |
|---|---|---|---|---|
| 渲染期模板 | 角色卡/世界书 EJS | 自研解释器 `parsing/assistant/ejs/`(lexer→parser→ast→exec) | 60+ **封闭内建枚举**(`value.rs:11-116` Builtin),无 IO/网络/动态求值 | 调用深度 128(`env.rs:32`),`evalTemplate` 嵌套 16(线程局部 `EVAL_TEMPLATE_DEPTH`,`exec.rs:21-26`) |
| 脚本期 | 角色卡/全局 tavern_helper 脚本 | rquickjs 沙箱 `scripts/` | TavernHelper 兼容桥(见下),桥外无能力 | 每次执行独立 Runtime(quickjs 非线程安全天然隔离);`set_interrupt_handler` 合作式超时 1s + 内存 64MB(`runtime.rs:30-69`);经 `spawn_blocking` 串行(`run_scripts.rs:115-132`) |
| 工具期 | `data/plugins/tools/*.json` | 白名单表达式求值器 `plugins/mod.rs:108-128` | 必须以 `return/result =` 开头,唯一变量 `args`;白名单函数(JSON/String/Math)+ 成员方法;**无循环、无函数定义、无环境** | 注册进 ToolRegistry 后受统一权限层与单工具超时约束 |

**EJS 解释器架构**:模板编译为单一 JS 程序(文本段→`__kedai_out__`,`<%= %>`→`String(...)` 包裹,`<% %>` 原样拼接,大括号跨标签配对;`mod.rs:91-188`);parser 语句级容错(错误收集后跳到下一语句边界恢复,`mod.rs:156`);Env 作用域链 `Vec<Rc<RefCell<HashMap>>>`(闭包捕获 Rc 引用,赋值可写回外层);**逐语句容错+整体失败回退原文**(`render.rs:46-52`),「无上下文容错」横切原则:读类函数缺上下文返回默认值,绝不 panic。`<#escape-ejs>` 块用控制字符占位符转义(`mod.rs:213-259`)。
**EvalBridge API 面**(`scripts/bridge.rs:108-196`):变量读写 6 函数(读为 JSON 快照注入,写经 `__kd_write_native` 落 ScopeVars)、`eventOn/eventEmit`(单次执行内有效)、`triggerSlash`(自定义 handler > SlashRegistry > 内置最小实现)、脚本元信息;扩展管理只读(install* 一律 throw)。**generate 宿主 handler**(`run_scripts.rs:10-44`)只认 `user_input/max_tokens/temperature`,`custom_api/tools/json_schema` 明确不支持;import handler 五类导入直调 service 绕过 HTTP。

## 第 8 章 mvu 变量系统(双协议 + 七作用域)

**核心结构**:直接操作 JSON 树,无独立 IR;`AssistantVars{tree: Value}` 根即 stat_data(`vars.rs:13-17`);路径归一化剥 `stat_data.` 前缀、点/斜杠双分隔、**过滤 `__proto__/constructor/prototype` 防原型污染**(`vars.rs:144-171`)。`PatchOp::{Replace,Delta,Remove,Move}` 四变体,各带 `reason: Option<String>`(`patch.rs:12-30`)。
**双协议解析**(`patch.rs`):
- `<UpdateVariable><JSONPatch>[...]</JSONPatch></UpdateVariable>`:RFC 6902 子集 + `delta` 扩展;`insert/set` 并入 Replace;delta 非数字整条跳过;未知 op 跳过。

## 第 16 章 安全模型横切

**第一篇小结——五条横切设计原则**(后续优化的评价基准):
1. **三层 JS 能力按信任度分级**,绝不 eval(第 7 章);
2. **无上下文容错**:读不到返回默认值、渲染失败回退原文、解析失败跳过条目——内容不丢、绝不 panic;
3. **幂等贯穿存储层**:建表/补列/回填/合并签名/checkpoint 重放全部可重复执行(第 10 章);
4. **镜像双写与游标回填**:message 作用域 = extra + scope_variables 镜像,引擎为唯一写者(第 8/10 章);
5. **稳定引用防重渲染**:nonce/seed/内容签名/in-flight 合并(第 13/15 章)。
