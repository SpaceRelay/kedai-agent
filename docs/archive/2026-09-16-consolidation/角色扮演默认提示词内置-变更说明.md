## 0. 问题定位(先说清边界)

`D:\kedai-android` **只是工具目录**(SDK / JDK / gradle / keystore / CDP 脚本,已核:无任何
`.rs` 源码),其构建包装器 `bin/acargo.bat` 明确 `KEDAI_CRATE=D:\kedai\server-rs`、
`bin/ata.bat` 先 `cd /d D:\kedai`。**Android 与桌面共用同一份源码**,不存在第二份需要同步的代码。

因此「Android 没有默认角色扮演提示词」的准确含义是:设置层默认值是**空串**,而非缺少源码。

修复前链路(逐项已核):

| 环节 | 行为 | 结论 |
|---|---|---|
| `params.rs::from_config` | `agent_system_prompt: RoleplayPromptConfig(String::new())` | 新装默认**空串** |
| `mod.rs` 字段属性 | `#[serde(default)]`(裸 `Default::default()`) | 缺字段仍落**空串** |
| `secret.rs::load` | 其他 10 余字段都有「空值 → 回退默认」,唯独本字段**没有** | 空值不物化 |
| `api/settings.rs:858` | 空值 → 预览层显示「内置默认角色扮演 / 文学创作模板」文案 | 面板/API 恒显示为空 |
| `context.rs:375` | 空串 → `custom_prompt=None` → 走 `build.rs` 的 `_` 分支 | 引擎**有**兜底模板,但措辞是 2026-08-16 的旧版(「视角遵循系统提示词与用户要求…」) |
| Win 端 `settings.json` | 已保存一份 1150 字用户调优版(「严格以提示词要求的视角和口吻输出…」) | Win 端完整,靠的是**文件值**,不是默认值 |

即两端差异的根因与前序记录一致:**提示词此前只以用户数据文件形态存在**。本次把它纳入代码默认。

## 1. 修复

### 1.1 `default_roleplay_agent_prompt()`(与 Win 端正用版逐字一致)

**落点**:`server-rs/src/services/settings_service/params.rs`(紧随 `default_task_agent_prompt()`)。

文本取自 Win 端数据目录 `%APPDATA%\com.kedai.app\data\settings.json` 的
`agent_system_prompt`,**逐字一致**(1150 字符,已用脚本反解 Rust 原始字符串与原文做过
byte-identical 校验,非手抄)。含五个标志性段落:`【创作总纲】`/`【角色扮演规则】`/`【写作要求】`/
`【剧情结构(模块化)】`/`【输出纪律】`。

**契约(与任务向默认词相反,不可混用)**:

- 必须保留 `{{char}}` / `{{personality}}` / `{{scenario}}` / `{{world_info}}` 四个宏占位符
  —— 由引擎宏系统按角色展开(见 `parsing/macros.rs`);
- `default_task_agent_prompt()` 则明确**不得**含 `{{char}}`。两者方向相反,有测试分别锁定。

### 1.2 两条生效路径

| 路径 | 改动 | 覆盖场景 |
|---|---|---|
| `from_config` | `RoleplayPromptConfig(String::new())` → `RoleplayPromptConfig(default_roleplay_agent_prompt())` | 全新安装、settings.json 缺失/损坏 |
| `load` 空值回填 | `if s.agent_system_prompt.0.trim().is_empty() { ... = default_roleplay_agent_prompt() }` | settings.json **已存在**但该字段为空(此前安装、旧版 Android 首装) |

回填位置紧跟 `mvu_vars_position` 回退之后,与 `search_endpoint` 等字段的既有回退**同一模式**。
语义对齐设置页文案与 [模式提示词边界.md](模式提示词边界.md):**空串 = 使用内置默认模板**。

### 1.3 兼容性

- **用户已保存的非空文本优先**,回填不会覆盖(有测试 `load_backfills_empty_roleplay_prompt_and_keeps_custom_text` 双向锁定)。
- **mode=`task` 显式清空(Some(""))不受影响**:走 `for_mode(Task)` 覆盖层分支,与扁平字段无关。
- **`RoleplayPromptConfig` 线格式不变**(`serde(transparent)`):settings.json 仍是裸字符串,
  老的写回文件(空串)读入时被回填,**磁盘形态在下次保存时同步为文本**。
- **引擎侧 `build.rs` 的 `_` 分支保留**:仅当 `for_mode(Roleplay)` 得到空串时才会走到;
  本版之后扁平字段默认非空,而显式清空仍需该分支兜底,故不动。
- 模式隔离(WP7)不退化:task 缺省仍是任务向词、roleplay 默认词含宏占位符、task 覆盖层不污染
  roleplay 扁平值 —— 三条均为既有测试 + 本版新增断言共同锁定。

## 3. 遗留说明

- **引擎 `build.rs` 的内置模板措辞与本默认词不一致**(旧版「视角遵循系统提示词与用户要求…」
  vs 本版「严格以提示词要求的视角和口吻输出…」)。本版只统一「设置层默认值」这一路;
  引擎模板仅在**显式清空**时兜底,用户可见影响面为「主动清空提示词」的少数场景,
  故本轮未改其文本(改它等于改变显式清空用户的既有生效值,属另一项决策)。若要求全链路口径单一,
  后续可把 `build.rs` 的 `_` 分支改为引用本函数。
- **Android 老安装的既有空值需一次读取才回填**:回填发生在 `load`,即下次启动生效;
  进程内已加载的设置不受影响(需重启服务进程,与 MAINTENANCE 既有说明一致)。
