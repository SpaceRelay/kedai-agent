## 二、批次 A：EJS 加固 + 自研引擎冻结（P0,最高优先）

**威胁模型**:角色卡属外部不可信输入。EJS 渲染在 async fn 内**同步**执行
(`agents/engine/worldbook.rs:85,119`、`messages/context.rs:257`、`parsing/assistant/inject_tag.rs:148`)。
一个 `while(true){}` 即挂死 tokio worker(单卡 DoS);深嵌套表达式致栈溢出(进程 abort,不可 catch)。

### A.1 迭代与时间预算(封堵挂死)

**现状**:三处裸 loop——`Stmt::For`(`ejs/exec.rs:106-122`)、`Stmt::ForOf`(`:132-141`)、
`Stmt::While`(`:145-156`);全文件仅有 `MAX_CALL_DEPTH=128`(`ejs/env.rs:32`,约束调用深度)与
`MAX_EVAL_TEMPLATE_DEPTH=16`(`ejs/exec.rs:26`,约束嵌套渲染),**无迭代/时间上限**。

**设计**(复用 `exec.rs` 已有的 thread_local 模式;**不放 `Env` 字段**——`render_nested`
(`exec.rs:31`) 会重建 `Env`,字段会被重置):

```rust
// ejs/exec.rs 顶部,与 EVAL_TEMPLATE_DEPTH 并列
std::thread_local! {
    static RENDER_STEPS: Cell<u64> = const { Cell::new(0) };
    static RENDER_DEADLINE: Cell<Option<Instant>> = const { Cell::new(None) };
}
const MAX_RENDER_STEPS: u64 = 200_000;     // 单次渲染总迭代预算
const MAX_RENDER_MILLIS: u128 = 2_000;     // 单次渲染墙钟上限

/// 循环每轮收费:先扣迭代预算,再查墙钟。Err 天然沿 exec 的 Result 冒泡。
fn charge_step() -> Result<(), String> {
    RENDER_STEPS.with(|b| {
        let left = b.get();
        if left == 0 { return Err("EJS 渲染超出步数预算".into()); }
        b.set(left - 1);
        Ok(())
    })?;
    RENDER_DEADLINE.with(|d| {
        if let Some(t0) = d.get() {
            if t0.elapsed().as_millis() >= MAX_RENDER_MILLIS {
                return Err("EJS 渲染超出时间预算".into());
            }
        }
        Ok(())
    })
}
```

- 三处循环体首行插入 `charge_step()?;`(`exec` 签名 `exec.rs:56` 已是 `Result<Flow,String>`)。
- 预算在渲染入口初始化:`ejs/mod.rs:80 render_template_with_ctx` 进入时
  `RENDER_STEPS.set(MAX_RENDER_STEPS)` + `RENDER_DEADLINE.set(Some(Instant::now()))`;
  用 RAII guard 在函数退出时恢复旧值(防嵌套渲染串味;`render_nested` 复用同一渲染入口)。
- **时间检查放循环内,而非外层 `tokio::time::timeout`**:同步函数无法被 async 超时打断,
  而在循环内查 `Instant::elapsed()` 既是最廉价的位置,又覆盖「无界时间累积」的唯一来源,
  无需把所有调用点改 `spawn_blocking`。
- **失败后果可控**:`parsing/assistant/mod.rs:347-362` 已有「单块渲染失败 → 跳过该块、回退原文」
  的既有语义,预算耗尽自动走这条路径——不 panic、不牵连其他块。

### A.2 解析深度守卫(封堵栈溢出)

**现状**:`ejs/parser.rs` 全文件无 depth 计数(`grep depth|MAX_|recursion` 零命中)。

**设计**(在 `Parser` 结构体加字段,而非给 17 个函数加参数):

```rust
const MAX_PARSE_DEPTH: usize = 256;

/// 三个递归枢纽统一入口宏/辅助:进入 +1 校验,退出 -1
fn enter(&mut self) -> Result<(), String> {
    self.depth += 1;
    if self.depth > MAX_PARSE_DEPTH { return Err("EJS 表达式嵌套过深".into()); }
    Ok(())
}
fn leave(&mut self) { self.depth = self.depth.saturating_sub(1); }
```

**守卫点必须为 3 个**(否则有绕过路径):

| 守卫点 | 覆盖的递归链 |
|---|---|
| `parse_assign:289` | 二元/右结合链(含 `:301` 右结合赋值、`:316/318` 三元两分支) |
| **`parse_unary:441`** | **一元链(`:447/454/461/467/476` 自递归)——`!!!!…x` 即从此爆栈,漏掉此处守卫无效** |
| `parse_primary:552` | 原子链(`parse_postfix:487`、`parse_expr:285`、数组 `:670`/对象 `:686`/模板 `:556` 内的 `parse_assign` 均汇聚于此) |

- 因守卫覆盖参数与字面量入口方法,`parse_param_list:259`、`parse_func_tail:248`、
  `parse_arrow_body:722` **无需单独加守卫**(它们经由上述三点)。
- 子解析器必须继承深度:`parser.rs:565 Parser::new(&exprs[i])`、`:612 Parser::new(self.toks)`
  (probe)改为 `Parser::with_depth(toks, self.depth)`。

pub(crate) enum TaskTerminal {

| 预算「一刀切」误杀正常大循环 | 低/中 | `MAX_RENDER_STEPS=200_000` 远高于正常卡用量;补「正常 1000 次循环通过」反向测试 |
| ESLint 引入后 errors 墙 | 高/低 | 先 warn 档 + ratchet;断言类规则不设 error |
| pre-push hook 未版本化,换机丢失 | 高/低 | 提供 `tools/install-hooks.ps1` 一键安装,并在 `MAINTENANCE.md` 登记 |
| 既有测试本身不稳定(`tests/tasks.rs` 13 处 `sleep`、`assistant.rs` 轮询) | 中/中 | 门禁先建基线;flaky 用例登记核对表并单独修(不在本计划范围扩张) |

**全局回滚**:每批次独立 commit;若某批次验证失败,`git revert` 该 commit 即可,
不影响其他批次——这是选择「先提交基线」的核心收益。

## 十二、Definition of Done

1. `tools/check-all.ps1` 全绿(含新增 Rust 分层规则、lint、测试计数校验)。
2. `build.ps1` 门禁生效:人为制造一个失败测试,构建被中止;`-SkipChecks` 可绕过。
3. `tools/hooks/pre-push` 安装并可证明拦截一次推送。
4. 总验收断言 ①②③ 全通过(含 `!!!!…x` 一元链用例)。
5. 六模式集成测试全绿;`multi` 委托 `solo`;取消兜底口径统一;五收尾入口合一。
6. 生产 `.expect(` 除白名单外零命中;HTTP/SSE 错误形状同构。
7. `data_raw` 并发写测试通过(无丢更新、冲突可识别)。
8. 协议共享 fixture 双端断言绿。
9. 文档数字与 `tools/count-tests.mjs` 自动统计一致;核对表全项「已验证」。
10. `docs/ARCHITECTURE-3H.md` 模块代际清单与代码实际一致(含偏差登记章节)。
