## 0. 实测结论:交互功能本身没有坏

用真实卡 `94dc10fa-…png`(V3,`first_mes` 仅 `<MN>`,首楼由「开局美化」正则 13885 字符
替换体生成)在隔离实例(端口 3055 / 数据副本 / `KEDAI_WEB_DIST=web/dist`)内真实点击:

| 操作 | 结果 |
|---|---|
| 选身份「训练员」 | ✅ 描述框更新,自定义容器 `display:none` |
| 选场景 / 世界 | ✅ 按 `dict` 更新 |
| 选马娘「自定义」+ 输入名字 | ✅ 容器显示,描述框变「哦?原来你想见的是——【特别周】!」 |
| 点「开始你的特雷森物语」 | ✅ 剪贴板 RPC 发出、`alert` 弹出「设定已锁定…」 |
| **JS 未授权时**做上述操作 | ❌ 描述框不变、点击无反应,**且界面无任何提示** |

前置条件是「HTML 渲染已开 **且** JS 已授权」。因此本轮不重做交互实现,只修三处真实缺陷。

「随选项切换世界书条目状态」同样生效:机制不是卡内写代码,而是**条目 keys 精确等于
选项文案**(`野史大学习` / `人形马薄荷` / `愉快的同居生活开始了` …),提交时选项文本进
提示词触发注入。`generate-raw` 实测:A 组注入 A 两条、切到 B 组注入 B 两条且 A 不再注入;
面板停用条目后注入数 12→10;自定义文本不误触发。

## 1. 修复总览

| 编号 | 问题 | 根因 | 修复 | 落点 |
|---|---|---|---|---|
| F1 | 世界书条目 `depth` 不生效,扫描窗口恒为 4(正确性) | 解析只读顶层 `depth`,缺省 4;而角色卡导出把 depth 放在 `extensions`(同文件 `probability`/`use_probability` 已有 extensions 回退,唯独 depth 漏了) | `depth` 解析补 `extensions.depth` 回退,与 probability 同一写法;`role` 抽出 `read_role` 并兼容 ST 数字 `0/1/2` + `extensions.role` | `parsing/world_book.rs` |
| F2 | 卡内 CSS 注释吞掉紧随其后的声明(视觉) | 声明切分无注释处理:`/* 说明 */\n background-image: …` 的属性名被解析成含注释的串,不匹配 `^[a-z-]+$` → 整条声明被丢弃 | 新增引号感知的 `stripCssComments`,在 `sanitizeScopedCss` 与 `sanitizeCssDeclarations` 入口各剥一次(注释含 `{}` 会先破坏顶层块切分,故必须在切块前) | `web/src/cssSanitize.ts` |
| F3 | 「HTML 已开 + JS 未授权」无任何提示(可发现性) | 引导条 `renderHintVisible` 只覆盖 `!renderHtml`;「一键开启」只置 `renderHtml=true`,注释所称「并顺带提示可再授权 JS」并未实现 | 抽出 `renderHints.ts` 判定两条提示(HTML 未开 / JS 未授权),各自独立 dismissed 集合;新增 JS 授权提示条与授权入口 | `web/src/renderHints.ts`(新)、`components/ChatTopbar.vue` |
| F4 | 剪贴板失败被静默当成成功(行为契约) | 宿主 `clipboard-write` 失败 `return false` → `reply(true,{value:false})` → 沙箱 `writeText` resolve → 作者脚本 `.then()` 照常弹「设定已锁定」 | 失败改抛错,经 host `rpc-result(ok:false)` 让沙箱侧 reject,落到作者 `.catch()`;`execCommand('copy')` 取不到选区文本时返回 false(不再谎报) | `sandbox/dom-rpc.ts`、`sandbox/boot-script.ts` |
| F5 | 赛马娘卡回归夹具与生产形状不一致 | 夹具 `CONTROLS` 混入 `div` 条目,而真实 `gatherControls` 只采集 `input/select/textarea/button`;掩盖了「div 门面靠 `gatherIdMap` 提供」这条真实路径 | 夹具改为真实形状 + 独立 `ID_MAP`;新增用例锁住 div 门面数据源与写回 | `sandbox/uma-creation.test.ts` |

### F1 的影响面(为什么优先级最高)

真实三卡的 `depth` **全部**写在 `extensions`(顶层无),解析一律落到缺省 4:

| 卡 | 条目数 | `extensions.depth` 取值 | 受影响的 `enabled && !constant` 条目 |
|---|---|---|---|
| 赛马娘Pretty Derby | 95 | 1 / 2 / 4 / 5 | 14(作者 1/2 → 被放宽到 4,多扫误注入) |
| 爱托邦 | 109 | 0 / 4 / 5 | 3(作者 5 → 被收窄到 4,漏扫) |
| 干物吸血鬼少女与夜间工作 | 54 | 1 / 4 | 23(作者 1 → 被放宽到 4,多扫) |

修复前决定性复现(关键词只在第 1 条、共 4 条消息):`野史大学习` 被注入 → 修复后不再注入;
关键词移回最后一条仍正常注入。修复前后条目解析分布由「全部 4」变为 `{1:4, 2:18, 4:71, 5:1}`,
与卡内 `extensions` 取值一致。

`role` 同类隐患一并消除:卡里是数字 `0`(system),旧解析只接受字符串;当前三卡全为 0、
与默认一致故无实际影响,但非 0 的卡会被忽略。

## 3. 残留

- **桌面 WebView2 的 `alert`/剪贴板未做物理实证**:本卡反馈闭环依赖 `alert`,Chromium 侧已
  实测可用;WebView2 需构建后在便携版内人工复验(与三轮文档 §4 同一限制)。若 `alert` 不弹,
  启用既列兜底(沙箱 shim `alert` → 宿主 RPC)。
- **面板回写会把解析后的 `depth` 固化到顶层**:F1 之后语义已正确;用户在世界书面板保存一次,
  条目 depth 便以顶层形态持久化,不再依赖 `extensions`。非缺陷,仅记录形态变化。
- `sticky`/`cooldown` 仍不参与匹配(见 `known-limitations.md` L1,有意裁剪,本轮未动)。
