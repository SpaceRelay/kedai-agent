## 一、批次 4:抽象收敛(建议作为下一个大批次,P1)

> 定位:纯结构重构,**行为不变**是硬要求;每项独立提交、独立测试护栏。触碰主链路(引擎/任务),
> 建议按 4.1 → 4.7 顺序,不要合并成一次大改。

### 4.1 四份截断重试合一 ✅ 已完成(2026-09-13,提交 f9cb40d;见 [抽象收敛与残余修复-变更说明.md](抽象收敛与残余修复-变更说明.md))
- **现状**:同一「截断 → 预算翻倍 + 封顶」算法有四份实现,封顶各异:
  `api/chat.rs`(`GENERATE_RAW_RETRY_MAX_TOKENS=32768`,2 次)、
  `agents/engine/executor.rs`(`doubled_heal_budget`,8192,1 次)、
  `services/task_engine/team.rs`(`trunc_heal_budget`,65536,1 次)、
  `services/task_service/executor.rs`(`retry_if_empty_output`,65536,**不要求 length**)。
- **做法**:抽公共纯函数(建议放 `agents/engine/util.rs` 或新 `retry_policy.rs`),参数化
  「封顶/次数/触发条件」;四路径改调用并保留各自封顶值(有场景依据),注释写清依据。
- **验收**:四路径回归测试(可用 mock 钩子 `[[trunc_text:]]`/`[[trunc_fail:]]`/`[[tool_raw:]]`);
  `cargo test` 全绿;`dist_hash` 不变(纯重构)。

### 4.2 `TaskBackend` 拆窄接口 ✅ 已完成(2026-09-13)
- **现状**:`services/task_core/backend.rs` 约 20 方法、唯一实现;`record_self_heals` 直接引用
  `agents::engine::executor::SelfHealRecord`(倒置不彻底);`plan_task_retry` 等把重试/解析算法
  当宿主能力;返回 `Arc<Mutex<AgentFlowService>>` 泄漏锁纪律。
- **落地**:按 ISP 拆 8 个窄接口(`TaskStore`/`TaskTrace`/`TaskSettings`/`TaskPromptKit`/
  `TaskFlowAccess`/`TaskEvents`/`TaskTerminalSink`/`TaskGenerator`),`TaskBackend` 保留为
  blanket impl 聚合别名(既有 `Arc<dyn TaskBackend>` 构造点零改动);重试与解析上移
  `task_engine/{retry,parse}.rs`;`record_self_heals` 改传中性 DTO `task_core::TruncationHeal`;
  `agent_flow()` 删除 → `TaskFlowAccess::current_flow()` 在宿主内部加锁,引擎不再见 `Mutex`。
  证据:`check-arch` 全绿(规则 C 未动)、`cargo test --workspace` 1004 passed / 0 failed、
  `tests/tasks.rs`(50)+`tests/task_events.rs`(9)未减。**未做**:`team.rs` 自有重试算法未合并
  (解析目标不同),`generate_text` 仍属宿主能力(含连接器调用与调用追踪落库)。

### 4.3 `AgentEngine` 依赖结构体分组 ✅ 已完成(2026-09-13)
- **现状**:`AgentEngine::new` 18 个参数(`agents/engine/mod.rs`),挂在 `app_state.rs` 单点构造。
- **落地**:收敛为 `EngineCore`/`EngineStorage`/`EnginePrompt`/`EngineExt` 四结构体,
  `new(core, storage, prompt, ext)`;字段类型不变;构造点按分组组装;
  `OnceLock` 回填已核实与入参顺序无关。见 [前端工具链与审计升级-变更说明.md](前端工具链与审计升级-变更说明.md) §一。
- **做法**:分组成 3–4 个结构体(如 `EngineCore`/`EngineStorage`/`EnginePrompt`/`EngineExt`),
  构造签名收敛;后续新依赖只改结构体,不动签名。
- **验收**:编译 + 全量测试;`agent_tools` 的 `OnceLock` 回填不受影响。

### 4.4 状态机 transition 非静默 ✅ 已完成(2026-09-13)
- **现状**:`agents/state_machine.rs` 的非法迁移调用点大量 `let _ = transition(...)`(仅日志)。
- **落地**:`transition` 本就返回 `Result`;新增 `transition_best_effort`(失败
  `tracing::warn!` 带 from/to 并返回 false),8 处 `let _ =` 调用点改用它(含清单外同类第 8 处);
  三处已用 `?` 传播的保持不动;新增 3 例测试(含 warn 日志断言)。同上文 §二。

### 4.5 错误类型收敛(渐进,勿一次替换)
- **现状**:`Result<_, String>` 遍布 server-rs(约 105 个文件),错误分类只在 HTTP 边缘反推;
  `err_json` 帮助函数在 8 个 handler 里重复。
- **做法**:先 `api/util.rs` 收口 `err_json`;再在 **services 边界**引入枚举
  (`ServiceError::{NotFound, Conflict, Upstream, Db, Validation}`)+ `From<String>`,
  只改**最高频 10 个服务**;`agents/` 内部保持 String(避免大范围波及)。
- **验收**:`check-arch` 规则 G(裸 `{error}` ratchet)不反弹;新增错误映射测试。

### 4.6 Cargo workspace 化(可选,根治双锁)
- **现状**:无根 `Cargo.toml`,server-rs 与 src-tauri 各持 lock;`check-lock-sync` 只是护栏。
- **做法**:根 workspace 收纳 `server-rs`/`src-tauri`/`launcher` 三成员,**一份 lock**;
  `launcher` 零依赖可保留独立(若 workspace 化影响 cxflags 行为需实测)。
- **风险**:Tauri Android 构建依赖 `gen/android` 与 target 布局,须完整回归双端构建;
  建议独立分支试验,失败可弃。
- **验收**:`npm run check:lock`(基线清空)、双端构建指纹一致、Android 双 ABI 出包。

### 4.7 工具名 6 处登记收敛
- **现状**:新增工具需改 6 处(注册/风险级/场景白名单/工具指南/渲染意图/前端白名单),
  漏改静默降级。清单见 `docs/威胁模型与残余风险.md` §四。
- **做法**:合并为单一 `ToolSpec` 表(注册时一次性携带 risk/sets/when/render),或写元测试
  遍历注册表断言 5 处映射齐全。
- **验收**:新增一个哑工具只需改 1–2 处;元测试能拦漏改。

## 八、本次会话的关键教训(避坑)

1. **别整删外置产物目录**:`D:\kedai-build` 下挂着 Android 构建的 junction 目标
   `android-app-build`,整删会让 gradle 报「无法创建目录/输入文件不存在」且文案不指向真因。
   只清 cargo 子目录;坏了就清 `gen/android` 的 gradle 增量状态重跑(踩坑 26)。
2. **bash 里传 Windows 绝对路径要加引号**:`-RustTargetDir 'D:\kedai-build'`,否则反斜杠被
   吃掉变成 `D:kedai-build`(相对路径),产物散落进仓库。
3. **自己写的门禁会误报**:`check-lock-sync` 需排除本仓自身包(发版时两锁自身版本本就不同步);
   新门禁上线后要预留「误报修正」时间,别让门禁成为构建的唯一阻塞点却无法调整(踩坑 23⑤)。
4. **后台命令的 exit code 不可轻信**:`cmd; echo "exit=$?"` 会让外层退出码恒为 0 ——
   判断构建成败要**读日志关键字**(`BUILD FAILED` / `FAIL]`),不要看退出码。
5. **`taskkill` / gradle / cargo 并发重活会互相踩**:Win 构建与 Android 构建**串行**
   (本机 16GB 内存,并发链接会崩,见 MAINTENANCE 踩坑 17)。
