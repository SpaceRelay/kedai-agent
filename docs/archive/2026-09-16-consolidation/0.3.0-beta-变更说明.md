## 一、版本号 0.2.1 → 0.3.0-beta

**为什么是 `0.3.0-beta` 而不是 `0.3.0beta`**:后者**不是合法 semver**,cargo 直接拒绝
(实测报 `unexpected character 'b' after patch version number`)。语义完全相同,但预发布
后缀必须用 `-` 连接。已实测 `0.3.0-beta` 通过 `cargo metadata` 校验。

改动 7 处声明 + 1 处文档(由 `tools/bump-version.ps1` 统一维护,`build.ps1` 开头的
`Assert-VersionConsistency` 把关):

| 文件 | 字段 |
|---|---|
| `package.json` / `web/package.json` / `src-tauri/tauri.conf.json` | `"version"` |
| `package-lock.json` | 顶层 + `packages[""]` **两处自身版本** |
| `server-rs` / `src-tauri` / `launcher` 的 `Cargo.toml` | `version = "…"` |
| `MAINTENANCE.md` | `版本:v…` 行 + 最后更新日期 |

### 顺带修复 `bump-version.ps1` 两个缺陷

1. **`packages[""]` 版本永远改不到**(真 bug):原实现每轮都从文件头
   `Match`/`Replace(count=1)`,替换后原位置**仍是合法匹配**,于是第二轮又命中同一处
   (把顶层改了两遍),`packages[""]` 始终停在旧版本 → lock 自身版本与 `package.json`
   不一致(严格校验下会被 `npm ci` 判为不同步)。已改为**替换后推进搜索偏移**再找下一处。
   本次实测:修复前顶层 `0.3.0-beta`、`packages[""]` 仍 `0.2.1`;修复后两处一致。
2. **不支持预发布后缀**:原校验 `^\d+\.\d+\.\d+$` 且注释称「后缀请手工评估」。
   现改为合法 semver 校验(`x.y.z` 或 `x.y.z-预发布`),并在拒绝时提示「后缀必须用 `-`
   连接,不能写成 0.3.0beta」,把这次踩到的坑固化成脚本行为。
   `MAINTENANCE.md` 的版本行正则同步支持后缀。

## 二、「更新内容」重写

原文案 4 条为**较早版本**的说明(任务模式/酒馆兼容/向量化记忆/提升稳定性),与本版实际
内容不符。按 0.3.0 的真实变更重写为 6 条,再**移除已过时的第 1 条「新增任务模式六种执行
方式」**——该能力在 0.2.1 已发布并公告(见
[0.2.1-关于与提示词同源-变更说明.md](0.2.1-关于与提示词同源-变更说明.md)),不应再作为
0.3.0 的新增项重复公告;且「六种」与正文列举的 5 种用户可见模式不一致(未列 legacy)。
移除后最终为 **5 条**(用户可读表述,不出现内部术语):

1. 新增命令执行能力:Agent 可调用命令完成任务(默认关闭;删除、提权等危险命令逐条确认,
   不享受任何授权豁免)
2. Android 端完成适配:新增 ROOT / Shizuku / 沙箱三档执行层,并修复手机端设置面板窄屏溢出
3. 提升稳定性:角色卡脚本与模板渲染加入资源上限,含死循环或超深嵌套的卡片不会再卡住程序
4. 修复并发编辑角色卡时,世界书、脚本与角色信息互相覆盖导致改动丢失的问题
5. 修复「关于」页多行文字挤成一行的排版问题,版本号改为自动读取实际运行版本

依据文档:第 1、2 条见
[命令执行层与Android三档执行器-变更说明.md](命令执行层与Android三档执行器-变更说明.md);
第 3 条见 EJS 资源预算(commit `96b9c58`);第 4 条见 `data_raw` 事务化(commit `5abcd7e`);
第 5 条见本文档 §三。

## 三、关于界面排版修复

**问题根因**:全局样式 `.sv-data-row .info span` 只设了 `color` 与 `font-size`,
**没有 `display: block`**。其它设置区的 `.info` 每个只放一个 `<span>`,所以看不出问题;
而「关于」页每段有 3~5 行说明,行内元素会**全部挤成一行**。又因全局 `.sv-data-row` 是
`align-items: center`,`<b>` 独占一行、其余挤在第二行,整体还垂直居中,观感错乱。

**修法**(不改全局样式,避免波及其它分区):

- 模板:去掉各行的行内 `style="align-items: flex-start"`,改用语义类 `about-block`;
- 新增 `<style scoped>`:`.about-block` 顶部对齐、`.info` 改 `flex-direction: column` +
  `gap: 6px` + `line-height: 1.55`;
- 更新内容每条加序号 `i`,用 flex + `tabular-nums` 固定序号宽度对齐,正文可正常换行。

**顺带改进(避免同类问题复发)**:版本号不再写死。改为 `onMounted` 调 `/api/health`
读后端编译期注入的 `version`(该端点一直返回 `env!("CARGO_PKG_VERSION")`),取不到时回退
常量 `0.3.0-beta`。这样关于页显示的就是**实际运行版本**,不会再出现 0.2.1 那种「发版后
忘记手改、关于页仍显示旧号」的情况。

## 四、验证

### 4.1 环境说明:后端产物须外置

本机 `server-rs\target` 下**新建的 exe 无法执行**(build script 报 `os error 5 拒绝访问`),
逐步排查确认是安全软件对「该目录下新建可执行文件」的实时防护(同目录下复制进去的既有
exe 可正常执行;`icacls` 正常;全量清空后依旧;非 junction)。故本次构建用外置产物目录。

为此给构建链补了参数支持(此前 `build.ps1` 硬编码 `server-rs\target`,外置时会误报
「Rust 编译失败:未生成 …」):

| 脚本 | 新增 | 作用 |
|---|---|---|
| `build.ps1` | `-RustTargetDir <path>` | 仅作用于 server-rs,不影响 src-tauri 便携版产物路径 |
| `build.ps1` | 自动把该路径传给门禁 | 避免 `check-all` 的 cargo 步骤回落到默认路径 |
| `tools/check-all.ps1` | `-RustTargetDir <path>` | 同口径传给 `cargo fmt/clippy/test` |

用法:`.\build.ps1 -RustTargetDir D:\kedai-build`。已记入 `MAINTENANCE.md §10` 条目 22。
