## 2. 关键实现说明

### WP2 收尾（`server-rs/src/services/task_service.rs`)
- 新增两个自由函数 `generate_step_retry` / `summarize_task_retry`（与 `finalize_run` 同层，可单测）:
  - 空内容且 `finish_reason == "length"` → `max_tokens` 翻倍（`saturating_mul(2)`，上限 `RETRY_MAX_TOKENS_CAP = 65536`）重试一次；
  - 空内容且非 length → `temperature = 0.7` 重试一次；
  - 重试前 `sleep(EMPTY_RETRY_BACKOFF)`（500ms)，重试后先查 cancel;
  - 仍空 → `Err("子任务返回空内容(finish_reason=…)")` / `"汇总返回空内容(finish_reason=…)"`。
- `run_task_background` 步骤段/汇总段改走上述辅助函数；返回值保持 `TaskGenOutput`（未简化回 String，为 WP4 铺路）。
- **顺手修复一处隐患**:`summarize_task_with` 之前忽略入参 `max_tokens`/`temperature`（误用 settings 默认值）,`generate_step_with` 是正确的；已改为使用入参。这也是此前 `cargo build` 两条 unused 警告的来源。

### WP3「部分完成」终态
- 后端：`set_result` 加 `status` 参数；汇总成功时 `final_plan` 含 error 步骤 → `status='partial'`，否则 `'done'`。`tasks.status` 无 CHECK 约束，无需迁移。
- 前端：`TaskStatus` 加 `'partial'`;`taskStatusLabel` →「部分完成」;`taskStatusClass` → `'active'`（黄色语义）。
- 注意：`partial` 是**终态**——前端轮询停止条件与后端测试 `wait_terminal` 均已把 `partial` 纳入终态集合。

### WP4 usage 落库与展示
- `schema.rs`：幂等新增 `task_usage` 表 + `idx_task_usage_task` 索引（与 tasks 同区，未复用 `llm_requests`，原因见其外键指向 sessions)。
- `task_service.rs`：新增 `record_usage`(model 取 `task_settings().model`，即合并 settings 后的有效模型）;`run_task_background` 三处落库：规划后 `phase="plan"`(`plan_task` 改为返回 `(Vec<TaskStep>, TaskGenOutput)`)、每步成功 `phase="step", step_index=i`、汇总成功 `phase="summary"`。新增 `usage_total(task_id)` / `all_usage_total()` 聚合查询。
- API:`GET /api/tasks/{id}` 响应增 `usage_total {prompt_tokens, completion_tokens, reasoning_tokens}`；新增 `GET /api/tasks/usage-total`（注册在 `{id}` 路由之前，axum 静态段优先）。
- 前端：`TaskDetail` 加 `usage_total`;`api/tasks.ts` 加 `getTaskUsageTotal`;`stores/task.ts` 加 `currentTaskUsage`/`globalTaskUsage` 与 `loadGlobalTaskUsage()`（进入任务模式与终态时刷新，当前任务累计由详情轮询带出）;`store.ts` 门面同步转发；Sidebar 任务模式统计块改绑「当前任务累计/全部任务累计」，上下文 TOKEN 格与命中率格隐藏；TaskBoard 状态行旁显示「累计 token X」。

### WP5 侧栏实时刷新（`web/src/stores/task.ts`)
- `loadTaskDetail` 返回 `Promise<boolean>`（详情签名是否变化，对外仍可直接 await 忽略返回值）;
- 轮询 tick 内签名变化即 `loadTasks()`——执行全程侧栏状态实时跳动，不再等到终态。

### WP6 启动日志 + 桌面双启动竞态
- `server-rs/src/lib.rs`:「Kedai 已启动」行补 `model` 字段，取 `state.model`（合并 settings 后的有效模型，与 engine 内一致）。
- `src-tauri/src/lib.rs`:
  1. 抽出 `show_main_window()`（导航+显示+聚焦，两条成功路径共用）;
  2. `run_server` 绑定失败但 `health_ok` 为真 → 记 info 日志「检测到已有 Kedai 实例，直接复用」并照常显示窗口（不再 exit 1)；不健康维持原报错路径；
  3. 启动成功/复用成功后 `clear_start_error()` 删除陈旧 `tauri-start-error.log`;`start_and_wait_ready` 增加 `log_dir` 参数。

### WP7 前端文案与测试
- `AgentPanel.vue`：新增 `planErrorCount`；出错步骤 >0 时进度行显示「完成 X/Y · N 步出错」。
