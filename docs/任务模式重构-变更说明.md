## 2. 各工作包说明

### WP1 后端拆分:`task_service.rs` → `services/task_service/` 目录模块

- **动机**:`task_service.rs` 单文件 1270 行,CRUD、SQL、执行引擎、提示词渲染、JSON 打捞、usage、取消令牌职责全挤在一起,改动相互踩踏。
- **做法**:沿用「目录模块 + `use super::*`」零签名改动模式(与此前 agents/engine、ejs 拆分同款),拆为六个子模块:`mod.rs`(TaskService 结构体/new/常量/CRUD/usage 聚合)、`db.rs`(行映射与全部落库方法)、`cancel.rs`(取消令牌)、`prompt.rs`(任务侧提示词模板与拼装)、`parse.rs`(plan JSON 解析与打捞 + 既有单测)、`executor.rs`(run/stop/规划/步骤生成/汇总/重试/后台执行)。纯搬移,零行为变化。WP4 后续追加第七个子模块 `events.rs`。
- **关键文件**:`server-rs/src/services/task_service/{mod,db,cancel,prompt,parse,executor}.rs`。
- **测试证据**:搬移后 `cargo test` 全绿,无任何用例改动即通过(等价性由既有测试网兜底)。

### WP2 消重复 + 消 panic

- **动机**:`generate_step_retry` / `summarize_task_retry` / `plan_task_retry` 三份逐行同构的空输出重试逻辑;`list_subtasks()` 等 DB 读取路径的 `unwrap`/`expect` 在线上会 panic。
- **做法**:泛型重试器 `retry_if_empty_output` 收敛 generate_step / summarize 两路同构重试(空输出分级规则不变:`finish_reason=length` → `max_tokens` 翻倍、封顶 65536;否则 `temperature=0.7`;退避 500ms;300s 总看门狗);`plan_task_retry` 因返回类型与流程异质保持独立。DB 读取路径改走 `read_or_log` + `log_query_failure` 优雅降级(记日志、返回空集合,不再 panic)。
- **关键文件**:`server-rs/src/services/task_service/executor.rs`、`server-rs/src/services/task_service/db.rs`。
- **测试证据**:既有空输出重试与 partial/截断打捞回归用例全绿,重试语义与报错文案不变。

### WP3 状态枚举化(DB schema 不动)

- **动机**:任务状态在 DB / Rust / TS 三处裸 String 靠注释对齐,`types.rs` 旧注释已过期(漏 `planning`/`partial`),新增状态无任何编译期护栏。
- **做法**:Rust 侧 `models/types.rs` 新增 `TaskStatus`(`types.rs:481`)/`TaskStepStatus`(`types.rs:535`)/`TaskSubtaskStatus`(`types.rs:576`)枚举,serde snake_case 字符串映射,落盘与 API JSON 零变化;`from_str_lossy` 容错回退 `Pending`;`TaskStep.status` 走字段级 `deserialize_with`(`de_step_status_lossy`,`types.rs:620`),LLM 产出的 plan JSON 里偶发未知状态不再炸反序列化。TS 侧 `api/types.ts` 裸 string 改 `TaskStepStatus`/`TaskSubtaskStatus` union;`taskStatus.ts` 加 exhaustiveness 软断言 `softNever`(`taskStatus.ts:14`),新增状态编译期报错。DB schema 不变(status 仍是 TEXT,不加 CHECK,避免迁移风险)。
- **关键文件**:`server-rs/src/models/types.rs`、`web/src/api/types.ts`、`web/src/taskStatus.ts`。
- **测试证据**:`cargo test` + `npm test -w web` 全绿;集成测试断言落盘/返回值字符串与重构前一致。

### WP4 任务事件 SSE 实时化

- **动机**:任务进度此前靠前端 1s REST 轮询刷新,「SSE task 事件」实为前端合成的伪事件,reducer 空操作。
- **做法**:
  - `SseEvent` 新增 `Task` 变体(`types.rs:407`):`task_id` + `kind`(created|status|plan|subtask|usage|deleted)+ 可选 title/status/detail;
  - `TaskService` 内嵌 `tokio::sync::broadcast::Sender`(`task_service/mod.rs:92`,容量 64,见 `events.rs` 的 `EVENTS_CAPACITY`),各 DB 写入方法(set_status/set_plan/set_subtask_status/record_usage/delete,含 `reset_task` 的 planning)落库成功后 `emit_event`;无订阅者不算错误;
  - 新端点 `GET /api/tasks/events`(`api/tasks.rs:74`):订阅 broadcast 通道逐条转发为 SSE data 帧,KeepAlive 30s、`Cache-Control: no-cache, no-transform`;接收滞后(Lagged)记 debug 跳过积压,通道关闭(Closed)结束流;路由注册于 `api/routes/misc.rs:50`(静态段优先于 `{id}`),鉴权走全局中间件 `security::guard`(挂载点 `api/mod.rs:85`)。
- **关键文件**:`server-rs/src/models/types.rs`、`server-rs/src/services/task_service/events.rs`、`server-rs/src/services/task_service/mod.rs`、`server-rs/src/api/tasks.rs`、`server-rs/src/api/routes/misc.rs`。
- **测试证据**:`server-rs/tests/task_events.rs` 新增 3 个集成测试(broadcast 事件序列断言 + HTTP 端点 smoke),全绿。

### WP5 前端订阅改造

- **动机**:1s 轮询开销与伪事件维护成本;事件驱动后进度应即时刷新且断线可自愈。
- **做法**:
  - `api/types.ts` 新增 `TaskEvent` 类型;
  - `api/tasks.ts` 新增 `streamTaskEvents`:fetch + ReadableStream 手动帧解析(可带鉴权 header),`AbortController` 主动关闭不触发 `onClose`(区分主动停止与意外断线);
  - `stores/task.ts` 删除 1s 轮询与全部合成伪事件,改事件驱动:`onTaskEvent` 按 kind 精确刷新(详情/列表/全局 usage 各走各的加载函数);三层防风暴与自愈——in-flight 合并(同资源请求进行中时事件合并为结束后补一次)、指数退避重连 1s 起步翻倍封顶 15s(`RECONNECT_MAX_MS = 15000`)、连接存活 1500ms(`CONNECT_SETTLE_MS`)判定为已恢复(复位退避、停兜底、全量刷新补偿)、断开期间 5s 兜底轮询(`FALLBACK_POLL_MS = 5000`,仅列表 + 当前详情);
  - `App.vue` 启动接线;伪事件删除,真实 task 事件透传 eventLog,DevTools 面板照常可见。
  - TaskBoard/AgentPanel/Sidebar 只改 store 对接,UI 不动。
- **关键文件**:`web/src/api/types.ts`、`web/src/api/tasks.ts`、`web/src/stores/task.ts`、`web/src/App.vue`、`web/src/sseReducer.ts`。
- **测试证据**:`web/src/api/tasks.test.ts`(新)、`web/src/stores/task.test.ts` 重写(事件驱动/断线/退避/兜底)、sseReducer/storeFacade 同步,`npm test -w web` 全绿 + `npm run build -w web` 通过。

### WP6 补测试缺口

- **动机**:stop 运行中任务、汇总路径空输出重试两条关键链路无测试锚定。
- **做法**:新增集成测试 `task_stop_running`(running 态 stop → 任务 ended、未完结子任务就地 ended)与 `task_summary_empty_output_retries_then_errors`(汇总空输出重试后终态 error,见 `tests/tasks.rs:316`);mock connector 新增最小钩子 `[[empty_if:子串]]`(`connectors/mock.rs:182`,提取函数 `extract_empty_if_marker`,`mock.rs:380`):仅当任一 system 消息含该子串时返回空内容,使「只让汇总空、规划正常」可表达。**语义发现**:汇总失败终态 = `error`,`partial` 仅用于「步骤失败但汇总产出成果」。
- **关键文件**:`server-rs/tests/tasks.rs`、`server-rs/src/connectors/mock.rs`。
- **测试证据**:两个新用例全绿,既有 stop_pending / 空输出重试用例不回归。

### WP7 提示词管线整合 + 抗多模式混淆(本档核心)

- **动机**:任务侧与引擎侧各自重复实现世界书过滤/注入合成/占位符渲染;任务侧外部文本裸拼进 system 无 `<UNTRUSTED_PROMPT_SOURCE>` 边界;模式隔离仅靠 `for_mode()` 一个 if 分支,属约定而非法式;设置面板「Agent 系统提示词」两模式共用一个输入框,用户无法感知独立存储语义。
- **做法**:
  - **A. 共享模块 `services/prompt_kit.rs`**:`constant_world_text`(`prompt_kit.rs:14`,enabled&&constant 过滤 + 排序 + 格式化)、`system_inject_text`(`:33`,Simple 合成 / Complex 仅 system 楼层)、`render_character_placeholders`(`:57`,两侧语义一致的 6 个占位符共享,task 专属占位符经扩展参数传入)、`untrusted_boundary`(`:100`,自引擎 `agents/engine/messages/build.rs` 移入共享,引擎金样测试 `prompt_order_golden_with_untrusted_boundaries` 原样通过);
  - **B. 类型级模式隔离**:`RoleplayPromptConfig(String)`(`settings_service.rs:43`)与 `TaskPromptConfig(String)`(`:55`)两个 newtype,serde transparent,settings.json 线格式零变化;`ModeSettings` 覆盖字段为 `Option<TaskPromptConfig>`(`:71`),task 覆盖值无法被误赋给 roleplay 扁平字段(类型不同源,编译期防呆);`for_mode()` 中 task 覆盖层 `None` 时回退内置任务默认词 `default_task_agent_prompt()`,不回退 roleplay 人设词;
  - **C. 任务侧 untrusted 边界**:persona / 世界书 / 注入文本 / Agent 提示词全部加 `<UNTRUSTED_PROMPT_SOURCE>` 包裹,与引擎防注入水位拉齐;规划器(plan_task)维持「不注入 Agent 提示词与注入文本」语义不变;
  - **D. 双向污染测试矩阵**:forbidden 泄漏(task 执行/汇总产物不含 roleplay 人设词与 `{{char}}` 原文)、`for_mode` 三分支、serde 线格式读写对称、API 级 roleplay 不受 task 覆盖影响;
  - **E. 设置 UI 标注**(`AgentSettingsSection.vue`):「Agent 系统提示词」字段旁加模式徽标(任务模式专属/角色扮演专属,`modeBadgeText` :24)+ 说明行「该提示词按模式独立存储,互不影响。」(:64),placeholder 与「恢复默认」按钮文案按模式区分(task 模式为「恢复任务模式默认提示词」,`resetPromptLabel` :32);不动存储结构与 API;
  - **F. 文档**:新增 `docs/模式提示词边界.md`(两模式提示词来源/回退规则/注入边界/untrusted 包裹约定)。
- **关键文件**:`server-rs/src/services/prompt_kit.rs`、`server-rs/src/services/settings_service.rs`、`server-rs/src/services/task_service/executor.rs`、`server-rs/src/agents/engine/messages/build.rs`、`web/src/components/settings/AgentSettingsSection.vue`、`docs/模式提示词边界.md`。
- **测试证据**:污染矩阵全部用例全绿;`prompt_kit` 单测与引擎金样测试原样通过;`settings_service` 单测锚定类型隔离与线格式兼容。

## 5. 维护指针

- 任务事件机制改动前请先读 `server-rs/src/services/task_service/events.rs` 头部注释(发射时机约定:仅在 DB 写入成功后发射)。
- 新增任务/步骤/子任务状态:Rust 三个枚举 + TS union + `taskStatus.ts` 文案映射三处同步,`softNever` 会在编译期报漏。
- 新增设置字段涉及双模式时,继承/隔离选择规则见 `docs/模式提示词边界.md`;task 覆盖层新字段默认「继承」语义须显式声明。
- 汇总失败 = `error` 终态;`partial` 仅用于「步骤失败但汇总产出成果」(WP6 语义发现,勿混用)。
