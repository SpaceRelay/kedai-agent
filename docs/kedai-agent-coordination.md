# Kedai 协调系统提示词与 Agent 执行流程指南

本文档提供一套与 Kedai harness 协调工作的**主系统提示词**与**内置执行流程**说明,
以及流程的导入/导出格式。适用模式:`CUSTOM`(自定义流程)与 `AGENT`(工具循环)。

## 一、主系统提示词(建议)

以下文本可直接粘贴到「设置 → Agent → 系统提示词(Agent 模式)」文本框。
它与 Kedai 的内置机制对齐:

- 使用 Kedai 酒馆宏:`{{char}}`、`{{user}}`、`{{world_info}}`(世界书注入点,不写则世界书不注入)、
  `{{personality}}`、`{{scenario}}`、`{{lastUserMessage}}`、`{{getvar::键}}` 等;
- 使用 mvu 变量协议:`<UpdateVariable>` 块持久化状态;
- 中文输出优先,与默认角色扮演语义一致。

```
你是 {{char}} 的扮演者与文学创作者,与用户进行沉浸式角色扮演 / 文学创作。
背景设定:{{personality}}
{{scenario}}
世界书(当前已命中的设定,必须严格遵循,冲突时以世界书为准):
{{world_info}}

【协作规则】
1. 视角与口吻:严格以 {{char}} 的第一人称视角和口吻输出,不要出现旁白标题、
   「以上是回复」「作为AI」等元文本;角色设定与世界观保持一致。
2. 用户指令优先:用户提出的字数、风格、视角、情节走向要求必须服从;
   用户提问必须在本轮正面回答,不允许回避。
3. 状态持久化:若上下文中存在「当前状态」区块,当其中的数值/属性/物品/剧情标记
   发生变化时,必须在本轮回复末尾输出 <UpdateVariable> 块(JSON 数组格式),例如:
   <UpdateVariable><JSONPatch>[{"op":"replace","path":"/hp","value":88}]</JSONPatch></UpdateVariable>
   支持操作:replace(赋值)/ delta(增量加减)/ addvar(追加)/ remove;状态无变化则不输出;
   纯状态更新时正文可以为空。除 <UpdateVariable> 外,不得输出任何自定义 XML/HTML 标签。
4. 变量读取:状态以「当前状态」区块为准;不确定时不要臆造数值。
5. 输出纪律:一次只输出角色回应本身;若需要分段,使用空行,不使用 Markdown 标题。
```

> 提示:主提示词留空时,服务端使用内置默认角色扮演提示词;内置流程的
> 步骤级提示词(`[本步指令]`)会追加在主提示词之后,两者互补,不会冲突。

### 状态自动注入(引擎行为)

只要会话存在变量树(角色卡 `[InitVar]` 条目 / 酒馆助手插件 / 历史更新产生的状态),
引擎会**自动**把「当前状态」(stat_data JSON)+「状态更新协议」拼入上下文(system 或
最新 user 消息尾部,跟随「变量状态注入位置」设置)——即使角色卡没有
`{{format_message_variable}}` 常驻条目,模型也能看到状态并按要求输出 `<UpdateVariable>`。
无需在角色卡里手动加状态条目;若角色卡已有该条目,状态会同时出现在世界书与自动注入块中,内容一致。

### 反思提示词(建议)

「设置 → Agent → 反思提示词」:留空时用内置规则检查(空输出 / 截断 / 未答疑问);
填写后,deep / agent / custom 三种模式的反思步骤都会调用一次 LLM 按本提示词判定草稿,
判定结果须以 `PASS`/`通过` 或 `FAIL`/`不通过` 开头,失败自动重试(最多 3 次),
无法解析时自动回退内置规则。以下文本与主系统提示词、内置流程的「反思质量」步骤配套:

```text
你是 Kedai 的草稿质量检查员。你会收到 [用户输入] 与 [模型草稿] 两部分,请只判定草稿是否合格,不要修改或重写草稿。

按以下标准逐项检查:
1. 需求符合度:草稿是否服从用户提出的字数、风格、视角、情节走向要求;用户提问是否被正面回答,未回答即不合格。
2. 人设与世界观:是否与角色设定、世界书内容一致,有无明显冲突或臆造事实。
3. 输出纪律:是否以角色第一人称视角与口吻输出;有无旁白标题、「以上是回复」「作为AI」等元文本;有无除 <UpdateVariable> 外的自定义 XML/HTML 标签;是否包含反思或推理过程本身。
4. 完整性:草稿是否被截断(结尾半句、段落不完整);若上下文存在「当前状态」且状态发生变化,是否已输出格式正确的 <UpdateVariable> 块(<UpdateVariable><JSONPatch>[JSON 数组]</JSONPatch></UpdateVariable>);状态无变化时是否画蛇添足输出空块。
5. 语言质量:有无明显语病、错别字、前后矛盾。

判定输出(严格遵守):
- 全部达标:第一行输出 PASS 或「通过」。
- 任一不达标:第一行输出 FAIL 或「不通过」,第二行起用一句话指出主要问题(如:字数不足 / 未答疑问 / 视角漂移 / 结尾截断 / 状态未更新 / 非法标签 / 人设冲突),供修订参考。
- 第一行只能是 PASS / 通过 / FAIL / 不通过 之一,否则视为无效判定。
```

> 注意:反思消息不走酒馆宏展开,提示词中请直接写「角色」等字面词,不要使用 `{{char}}` 等宏;
> 反思调用温度固定 0.3、输出上限 512 token,判定应简短明确。

## 二、内置流程:「文学创作协调流程」

首次运行(或旧版空配置迁移)时自动注入流程库,默认选中并启用。四个步骤:

| 步骤 | 动作 | 生成 | 职责 |
|---|---|---|---|
| 理解意图 | direct | 否 | 提取用户要求的字数/视角/情节/风格,规划回应,不输出正文 |
| 起草正文 | direct | 是 | 以 `{{char}}` 视角输出完整正文,服从要求,状态用 `<UpdateVariable>` 持久化 |
| 反思质量 | reflect | — | 检查字数、疑问回答、视角一致、截断;输出 PASS / FAIL |
| 修订输出 | direct | 是 | 按反思结论修订;通过则原样输出草稿 |

协调点:

- **步骤级提示词**以 `[本步指令]` 追加到系统提示词末尾,支持全部酒馆宏与
  `{{setvar}}/{{getvar}}` 跨步骤传递;
- 反思步骤使用内置规则(空输出 / 截断 / 未答疑问),也可在「Agent 设置 → 反思提示词」
  填入自定义判定词,启用 LLM 反思;
- 每步生成后 mvu 变量补丁立即应用,后续步骤可见;反思重试会回滚该步变量基线,
  避免非幂等补丁重复应用。

## 三、流程库:选择 / 导入 / 导出

「设置 → Agent 执行流程」面板:

- **当前流程**:下拉切换流程库中的流程(立即生效,`CUSTOM` 模式使用当前选中项);
- **＋ 新建**:创建空流程(未启用),随后添加步骤;
- **⧉ 复制**:复制当前流程为新流程(新 id,名称加「副本」);
- **🗑 删除**:删除当前流程,服务端自动回退到第一个;
- **导入流程(JSON)**:接受三种格式,导入后立即入库并选中;
- **导出流程(JSON)**:下载当前流程(不含 `id`,重新导入即为全新流程)。

导入支持的 JSON 格式:

```jsonc
// 1) 单流程(推荐)
{ "name": "我的流程", "description": "可选", "enabled": true, "steps": [ /* … */ ] }

// 2) {config} 包装(与 PUT /api/agent-flows 请求体一致)
{ "config": { "name": "我的流程", "enabled": true, "steps": [ /* … */ ] } }

// 3) 完整流程库(取当前选中项;跨实例备份迁移用)
{ "current_flow_id": "…", "flows": [ /* … */ ] }
```

步骤字段与后端 `PlanStep` 对齐:

```jsonc
{
  "id": "s1", "name": "理解", "enabled": true, "goal": "理解用户意图",
  "action": "direct", "generates": false,
  "system_prompt": "步骤级提示词(支持宏,以 [本步指令] 追加)",
  "temperature": 0.7, "max_tokens": 4096,
  "tools": null           // null=不用工具;[]=全部;["read","search"]=白名单
}
```

校验规则(启用时):至少一个启用步骤、至少一个 `direct`+`generates=true` 步骤、
`action` 仅 `direct|reflect`、reflect 步不得带提示词、温度 0–2、输出上限 1–32768。

## 四、数据文件

- 流程库:`data/agent_flows.json`(旧版单流程格式自动迁移);
- 主系统提示词:`data/settings.json` 的 `agent_system_prompt`(留空 = 内置默认);
- 反思提示词:`data/settings.json` 的 `reflect_prompt`(留空 = 内置机械规则检查)。
