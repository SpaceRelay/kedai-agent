## 2. 任务模式 Agent 提示词丰富

**落点**:`services/settings_service/params.rs` 的 `default_task_agent_prompt()`。

原文本仅一句话(约 90 字)。补充三节:`【工作方式】`(先理解目标与交付物、含糊时的处理约定、
先用工具查证再作答、不边做边改方向、完成后自查)、`【质量标准】`(宁愿收窄范围做扎实、
不得编造来源与数据、输出语言跟随用户)、`【输出纪律】`(只输出结果本身、不用元文本开场收尾、
Markdown 标题限制)。

**边界**:该提示词与固定的规划器/执行者/汇总者内置指令(`task_service/prompt.rs`)职责互补——
内置指令管「这一步产出什么形态」,本提示词管「以什么姿态、按什么标准做事」,故不重复 JSON
契约等步骤级要求。两条既有测试约束保持不变:「任务执行智能体」字样保留
(`tests/tasks.rs` 断言缺省已注入默认词)、不得出现 `{{char}}`(`settings_service` 断言
task 默认词不得继承 roleplay 人设词)。

## 3. Win 端提示词同步到手机端

### 问题

「Win 端 agent 提示词」此前**只以用户数据文件形态存在**,不在仓库、不在代码:

| 提示词 | Win 端存放 | 手机端首装 |
|---|---|---|
| 主 Agent 运行时提示词 | `<data_dir>/AGENTS_RUNTIME.md` | **无该文件 → 引擎读到空 → 完全不注入** |
| 角色扮演 Agent 系统提示词 | `settings.json` 的 `agent_system_prompt` | 空(走内置模板兜底,与 Win 端自定义版有差异) |
| 反思提示词 | `settings.json` 的 `reflect_prompt` | 空(走机械规则) |

`D:\kedai-android\` 只是工具目录(SDK/JDK/gradle/keystore),不含源码;Android 与 Win 共用
同一仓库、同一份 `server-rs`(构建脚本 `KEDAI_CRATE=D:\kedai\server-rs`),因此两端差异**不是
代码分叉,而是「提示词只存在于 Win 的数据目录」**。

### 修复:把 Win 端提示词纳入代码内置默认

1. **主 Agent 运行时提示词** —— `runtime_prompt_service.rs` 新增
   `DEFAULT_RUNTIME_PROMPT`(内容与 Win 端现用版逐字一致,`{{char}}` 仍由引擎按角色名替换)。
   文件与旧文件都不存在时回退该默认;文件存在(用户保存过)时**文件优先**,不覆盖用户内容。
2. **反思提示词** —— `params.rs` 新增 `default_reflect_prompt()`(与 Win 端现用版一致),
   `RuntimeSettings::from_config` 用它作为默认值,使 deep/agent 模式开箱即有 LLM 质量判定。
   代价已在文档标注:非空时反思步骤会额外调用一次 LLM。用户清空即回到机械规则。
3. **角色扮演 Agent 系统提示词** —— 本版**未**改代码默认(当时判断为产品决策,见 §6 残留);
   后续已在 [角色扮演默认提示词内置-变更说明.md](角色扮演默认提示词内置-变更说明.md) 补齐:
   `params.rs` 新增 `default_roleplay_agent_prompt()`(与 Win 端正用版逐字一致),
   由 `from_config` 与 `load` 空值回填共同生效,手机端首装开箱即与 Win 端同源。

### 配套:env 隔离变量落实

`KEDAI_RUNTIME_PROMPT_DIR` 原被 6 个集成测试文件设置以隔离真实提示词,但 **src 侧从未读取**
(空操作)。现由 `RuntimePromptService::with_dir()` 正式支持:指定该目录时**关闭内置默认回退**
(空目录即视为无提示词)。测试语义因此真正生效,内置默认不会干扰 mock 断言。

### 顺带发现并修正:mock 工具白名单不忠实

补上反思默认词后,`tests/undo.rs` 3 个用例失败(快照 4 条而非 2 条)。根因不是默认词有问题,
而是 **mock 连接器无视本轮 `tools` 白名单**:反射轮只下发 `censor_text`/`revise_passage`/`read`,
mock 却照样按 `[[tool:write ...]]` 钩子再执行一次写工具,凭空多出副作用与快照。真实模型受
`tools` 参数约束不可能这样调用。

`mock.rs` 新增 `tool_offered(&params, name)`:tools 非空时仅响应白名单内的工具钩子
(tools 为空保持旧行为,兼容未声明工具的既有用例)。这使 mock 忠实于真实 API 契约,
上述 3 例随之恢复通过。
